# Implementation Plan: Context Compression & Shared Memory (Phase 2)

## Reference
- **ADR**: Pending (Will be ADR-010)
- **Roadmap**: Milestone 4.3 & 4.5

## Objective
Establish the local Context Compression Proxy and Cross-Agent Shared Memory mechanisms inside Docuvia, ensuring feature parity with `headroom`. This will dramatically reduce token costs for local AI agents and enable persistent learning across different editors.

## Tasks

### 1. Local Proxy Layer Setup (`artifacts/api-server/src/proxy/`)
- Create an Express or native Node.js HTTP server acting as a MITM (Man-In-The-Middle) proxy for LLM API calls.
- Implement an interceptor that captures `/v1/chat/completions` (OpenAI format) and `/v1/messages` (Anthropic format).
- **Goal:** Allow local AI agents (Cursor, Claude Code, Codex) to route traffic through `http://localhost:8080/proxy/v1` without changing their core implementation.

### 2. Context Compression Engine (CCR & Skeletons)
- Inside the proxy layer, implement the `SmartCrusher` and `CodeCompressor` logic (inspired by Headroom).
- **Functionality**:
  - Detect large raw source code blocks in the prompt.
  - Intercept those blocks, replace them with the AST Skeletons generated by the Microkernel from Phase 1, and store the original full text in a local SQLite cache.
  - Inject a system prompt instructing the LLM to use a new `docuvia_retrieve_original` MCP tool if it needs the uncompressed code.

### 3. Cross-Agent Shared Memory (`artifacts/api-server/src/memory/`)
- Implement a unified SQLite table `shared_agent_memory` with a schema that stores:
  - `agent_type` (e.g., 'cursor', 'claude-code', 'copilot')
  - `key` / `content` (the learned rule or fact)
  - `timestamp`
- Implement `headroom learn`-style logic: A background job that mines failed API proxy responses (e.g., where the LLM generated code that failed a linter/test step) and distills them into new rules.
- Expose these rules via an MCP tool `docuvia_read_shared_memory` so all connected agents benefit from the exact same evolutionary context.

### 4. Verification
- Add a test script `verify-proxy.ts` that sends a mock 50KB code payload to the proxy, verifying the payload is compressed to < 5KB before hitting the mock LLM endpoint.
- Verify `pnpm --filter @workspace/api-server run build` passes with zero errors.
