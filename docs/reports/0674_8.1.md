## Round 1 — Architecture & Design Review

### Design ↔ Implementation Alignment

**✅ Correctly implemented:**

1. CLI `sync` subcommand with post-commit hook stdin support
2. `POST /projects/:id/sync` has `requireApiKey` auth
3. Server-side sync performs real git clone + commit delta ingestion
4. ADR-021 shared core API implemented; local SQLite migration complete
5. `docuvia.sync` command registered in VS Code extension (extension.ts:447)
6. `docuvia.sync` registered in `package.json` contributes.commands
7. New `SyncService` calls authenticated endpoint (`POST /projects/:id/sync` with Bearer token)

### Gaps / Deviations

1. **❌ `POST /sync/push` has no `requireApiKey`** — The legacy CQRS outbox receiver remains unauthenticated. Any client can send arbitrary L3 node creation events to the server without API key. This is a 🔴 security risk.

2. **⚠️ Hardcoded `projectId = "1"` in `docuvia.sync` command** — The new VS Code sync command hardcodes `projectId = "1"` (extension.ts:462). This means the command always syncs to project ID 1 regardless of which workspace project the user intends. This is a 🟡 functional gap.

3. **⚠️ `CentralServerClient.sync()` is still dead code** — The new `docuvia.sync` command uses `SyncService` (from @workspace/core) instead of `CentralServerClient.sync()`. The `CentralServerClient.sync()` method remains implemented but never called from any extension code path.

## Round 2 — Code Quality & Security Review

### Strengths

1. `POST /projects/:id/sync` correctly uses `requireApiKey` middleware
2. `SyncService.sync()` sends Bearer token auth — the new sync command is properly authenticated
3. Advisory lock (`pg_try_advisory_xact_lock`) prevents concurrent sync conflicts
4. Transaction wrapping ensures atomic L3 node creation
5. Input validation via `SyncPushBody.safeParse()` Zod schema on the legacy endpoint
6. `docuvia.sync` command requires `getToken()` — fails early with error message if no token set

### Issues Found

1. **🔴 `POST /sync/push` unauthenticated** — No `requireApiKey` middleware. The endpoint accepts CQRS outbox events and writes directly to the database without any authentication. This is exploitable for unauthorized data injection.
   - **File:** `artifacts/api-server/src/routes/sync.ts` line 14
   - **Fix:** Add `requireApiKey` middleware or remove the endpoint if `/projects/:id/sync` fully supersedes it.

2. **🟡 Hardcoded projectId** — The `docuvia.sync` command uses `const projectId = "1"` (extension.ts:462). This should be derived from the workspace's `.docuvia/config.json` or similar project mapping.
   - **Fix:** Read projectId from the workspace's local configuration instead of hardcoding.

3. **🟡 Inconsistent auth patterns** — Three different auth mechanisms across sync surfaces: MCP_PAT Bearer token (SyncService → `/projects/:id/sync`), x-docuvia-token header (CentralServerClient → `/sync/push`), and no auth on the `/sync/push` route itself.

## Round 3 — Integration & Completeness Review

### Integration Correctness

1. CLI → Server sync flow works end-to-end (CLI reads git diff, sends to `/projects/:id/sync`, server ingests)
2. VS Code `docuvia.sync` → `SyncService.sync()` → `POST /projects/:id/sync` flow is properly wired end-to-end
3. The c3de191 refactor improved architecture (shared core, new CLI commands) without breaking sync functionality
4. The 130d37d commit added VS Code command parity including sync, using the new SyncService (not CentralServerClient)

### Missing Coverage

1. **Legacy endpoint auth** — `POST /sync/push` should either be authenticated or removed
2. **Hardcoded projectId** — Multiple-workspace users cannot target the correct project
3. **Dead SDK method** — `CentralServerClient.sync()` is unused and calls the unauthenticated endpoint; should be removed or rewired

## Overall Verdict

**⚠️ WARN**

No source code changes since the previous verification (2026-06-28). All 7 source file checksums are identical to report 0673. The sync CLI feature is functionally complete for both terminal and IDE users. The remaining gaps are:

1. **🔴 `POST /sync/push` unauthenticated** — The legacy CQRS outbox receiver at `artifacts/api-server/src/routes/sync.ts:14` has no `requireApiKey` middleware. **Recommendation:** Add `requireApiKey` to the router or remove the endpoint if `POST /projects/:id/sync` fully supersedes it.
2. **🟡 Dead `CentralServerClient.sync()`** — Now clearly superseded by `SyncService` from `@workspace/core`. **Recommendation:** Remove `CentralServerClient.sync()` or rewire it to the authenticated endpoint.
3. **🟡 Hardcoded `projectId = "1"`** — The `docuvia.sync` VS Code command always targets project ID 1. **Recommendation:** Read the project ID from the workspace's local `.docuvia/` configuration file.
4. **🟡 Inconsistent auth patterns** — SyncService uses Bearer token, CentralServerClient uses x-docuvia-token header, `/sync/push` has no auth.
