## Round 1 — Architecture & Design Review

### Design ↔ Implementation Alignment

**⚠️ Correctly implemented:**

1. CLI `sync` subcommand with post-commit hook stdin support (via`)
2. `POST /projects/:id/sync` has `requireApiKey` auth
3. Server-side sync performs real git clone + commit delta ingestion
4. ADR-021 shared core API implemented; local SQLite migration complete
5. `docuvia.sync` command registered in VS Code extension (extension.ts:447)
6. `docuvia.sync` registered in `package.json` contributes.commands
7. New `SyncService` calls authenticated endpoint (`POST /projects/:id/sync` with Bearer token)

### Gaps / Deviations

1. **❌ `POST /sync/push` has no `requireApiKey`** — The legacy CQRS outbox receiver remains unauthenticated (`sync.ts:14`, mounted at `index.ts:54` without auth middleware). Any client can send arbitrary L3 node creation events without API key.

2. **� Hardcoded `projectId = "1"` in `docuvia.sync` command** (extension.ts:462) — Always syncs to project ID 1 regardless of workspace config.

3. **🟡 `CentralServerClient.sync()` is dead code** — New command uses `SyncService`. `CentralServerClient.sync()` remains implemented but never called.

## Round 2 — Code Quality & Security Review

### Strengths

1. `POST /projects/:id/sync` correctly uses `requireApiKey` middleware
2. `SyncService.sync()` sends Bearer token auth
3. Advisory lock prevents concurrent sync conflicts
4. Transaction wrapping ensures atomic L3 node creation
5. Input validation via `SyncPushBody.safeParse()` Zod schema
6. `docuvia.sync` command requires `getToken()` — fails early with error message

### Issues Found

1. **� `POST /sync/push` unauthenticated** — No `requireApiKey` middleware. Exploitable for unauthorized data injection.
   - **File:** `artifacts/api-server/src/routes/sync.ts:14` (route), `artifacts/api-server/src/routes/index.ts:54` (mount)

2. **� Hardcoded projectId** — `const projectId = "1"` (extension.ts:462). Should read from workspace local configuration.

3. **🟡 Inconsistent auth patterns** — Three auth mechanisms: MCP_PAT Bearer token (SyncService), x-docuvia-token header (CentralServerClient), no auth on `/sync/push` route.

## Round 3 — Integration & Completeness Review

### Integration Correctness

1. CLI → Server sync flow works end-to-end
2. VS Code `docuvia.sync` → `SyncService.sync()` → `POST /projects/:id/sync` properly wired
3. Refactors did not break sync functionality

### Missing Coverage

1. Legacy endpoint auth — `POST /sync/push` should either be authenticated or removed
2. Hardcoded projectId — Multiple-workspace users cannot target correct project
3. Dead SDK method — `CentralServerClient.sync()` unused, calls unauthenticated endpoint

## Overall Verdict

**⚠️ WARN**

No source code changes affecting sync functionality since the previous verification (2026-06-29, report 0674). All 7 source file checksums are identical. The sync CLI feature is functionally complete for terminal and IDE users. Remaining gaps:

1. **🔴 `POST /sync/push` unauthenticated** — Legacy CQRS outbox receiver at `artifacts/api-server/src/routes/sync.ts:14` has no `requireApiKey` middleware. **Recommendation:** Add `requireApiKey` to the router mount or remove the endpoint.
2. **� Dead `CentralServerClient.sync()`** — Superseded by `SyncService`. **Recommendation:** Remove or rewire.
3. **� Hardcoded `projectId = "1"`** — `docuvia.sync` VS Code command always targets project ID 1. **Recommendation:** Read from workspace `.docuvia/` config.
4. **🟡 Inconsistent auth patterns** — SyncService (Bearer), CentralServerClient (x-docuvia-token), `/sync/push` (none).
