## Round 1 — Architecture & Design Review

### Design ↔ Implementation Alignment

**✅ Correctly implemented:**

1. CLI `sync` subcommand with post-commit hook stdin support
2. `POST /projects/:id/sync` has `requireApiKey` auth middleware
3. Server-side sync performs real git clone + commit delta ingestion
4. ADR-021 shared core API implemented; SyncService in `@workspace/core`
5. `docuvia.sync` command registered in VS Code extension (extension.ts:447)
6. `docuvia.sync` registered in `package.json` contributes.commands
7. `SyncService.sync()` calls authenticated endpoint with Bearer token

### Gaps / Deviations

1. **❌ `POST /sync/push` has no `requireApiKey`** — The legacy CQRS outbox receiver remains unauthenticated (`sync.ts:14`, mounted at `index.ts:54` without auth middleware). Any client can send arbitrary L3 node creation events without API key.

2. **❌ Hardcoded `projectId = "1"` in `docuvia.sync` command** (extension.ts:462) — Always syncs to project ID 1 regardless of workspace config.

3. **🟡 `CentralServerClient.sync()` is dead code** — New command uses `SyncService`. `CentralServerClient.sync()` remains implemented but never called from any command.

---

## Round 2 — Code Quality & Security Review

### Strengths

1. `POST /projects/:id/sync` correctly uses `requireApiKey` middleware
2. `SyncService.sync()` sends Bearer token auth
3. Advisory lock prevents concurrent sync conflicts
4. Transaction wrapping ensures atomic L3 node creation
5. Input validation via `SyncPushBody.safeParse()` Zod schema
6. `docuvia.sync` command requires `getToken()` — fails early with error message

### Issues Found

1. **🔴 `POST /sync/push` unauthenticated** — No `requireApiKey` middleware. Exploitable for unauthorized data injection.
   - **File:** `artifacts/api-server/src/routes/sync.ts:14` (route), `artifacts/api-server/src/routes/index.ts:54` (mount)

2. **� Hardcoded projectId** — `const projectId = "1"` (extension.ts:462). Should read from workspace local configuration.

3. **🟡 Inconsistent auth patterns** — Three auth mechanisms: MCP_PAT Bearer token (SyncService), x-docuvia-token header (CentralServerClient), no auth on `/sync/push` route.

---

## Round 3 — Integration & Completeness Review

### Integration Correctness

1. CLI → Server sync flow works end-to-end (cli → SyncService → POST /projects/:id/sync → git clone → ingestion)
2. VS Code `docuvia.sync` command → SyncService with proper auth
3. Post-commit hook stdin support enables git hook integration

### Missing Coverage

1. No test coverage for `POST /sync/push` security model — unauth'd route has zero test assertions
2. Multi-project workspace not supported — hardcoded `projectId = "1"` breaks all workspaces except project 1

## Overall Verdict

**⚠️ WARN**

The docuvia sync CLI is fully functional (CLI works, new endpoint has auth, shared core architecture correct), but has one critical security gap (`POST /sync/push` unauthenticated legacy endpoint), one functional gap (hardcoded `projectId`), and two code quality issues. The re-triggering change (`projects.ts` L1 topology) does not affect these findings. All findings are carried forward from prior verifications without change.
