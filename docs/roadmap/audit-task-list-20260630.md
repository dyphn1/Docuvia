# Audit Task List (2026-06-30)

This document aggregates the remaining unresolved issues from all past audit reports, sorted by severity.

## High Severity (Critical)
- [ ] **High**: **🔴 HIGH — No `git diff-tree -M` fast-path**: ADR-022 Pillar 2 specifies O(1) incremental computation. No implementation exists. Must re-parse all files on every ingestion run. (Found in: unknown)
- [ ] **High**: **🔴 HIGH — No cross-language / polyglot edge detection**: ADR-022 §SRE specifies API Contracts as Bridge Nodes and framework-specific AST tracking (tRPC, Next.js Server Actions). Not implemented. (Found in: unknown)
- [ ] **High**: **🔴 HIGH — No `git diff-tree -M` fast-path for incremental ingestion**: ADR-022 §2 specifies O(1) incremental computation using `git diff-tree -M`. No implementation exists. The current pipeline processes all files on every ingestion run. (Found in: unknown)
- [ ] **High**: **🔴 Missing `requireApiKey` on `/sync/push`** — Any unauthenticated client can POST CQRS events to modify any project's knowledge graph. This is a direct data integrity vulnerability. (Found in: unknown)
- [ ] **High**: **🔴 No project ownership check** — Even after auth, there's no verification that the authenticated user owns the `projectId` they're sending events for. Combined with missing auth = any authenticated user can write to any project. (Found in: unknown)
- [ ] **High**: **🔴 HIGH — No graph edges created**: The function only creates `review_tasks` entries of type "merge" when cross-project similarity is detected. No records are written to `node_links`, no `IMPLEMENTS`/`EXPLAINS`/`EVOLVED_INTO` edges exist, and no new table implements these edge types. The knowledge graph is not updated with cross-project relationships. (Found in: unknown)
- [ ] **High**: **🔴 HIGH — No temporal edges (EVOLVED_INTO)**: ADR-018 requires temporal edges tagged with commit SHA and diff summary. The `node_links` table has no `commitSha`, no `diffSummary`, and no temporal edge type. The `commit_l2_links` table maps commits to L2 nodes but does not track evolution between versions. (Found in: unknown)
- [ ] **High**: **🔴 HIGH — No self-healing re-anchoring**: ADR-018 requires a Background Janitor that validates links and re-anchors L3 rules when target commits disappear (rebase/amend). No janitor logic exists for this purpose. The `l2_nodes` and `l3_nodes` tables have no `content_hash` column, which is required for the re-anchoring algorithm. (Found in: unknown)
- [ ] **High**: **🔴 `POST /sync/push` has no auth** — `syncRouter` mounted without `requireApiKey` in `routes/index.ts:54`. Any unauthenticated client can send CQRS events (`CREATE_L3`, `UPDATE_L3`) to write arbitrary data to any project's knowledge graph. Severity: HIGH. (Found in: unknown)
- [ ] **High**: **🔴 `l2_nodes` schema missing `type` column** — Both DDL paths in extension.ts (lines 334-341 and 772-778) define `l2_nodes` without a `type` column. The recursive CTE at `_traverseViaSqlite()` does `LEFT JOIN l2_nodes n ON n.id = d.target_node_id` and selects `n.type`. This causes `SQLITE_ERROR: no such column: n.type` at runtime. **The SQLite CTE path crashes even if `node_links` table exists.** (Found in: unknown)
- [ ] **High**: **🔴 `node_links` table not created in local.db DDL** — Both schema creation paths in extension.ts create `l1_tags`, `l2_nodes`, `l3_nodes` but **omit `node_links`**. On fresh project initialization, local.db has no `node_links` table. The `_traverseViaSqlite()` method checks for `node_links` existence and returns `null` when missing, causing all traversals to fall back to in-memory BFS, which operates on an empty edge set. (Found in: unknown)
- [ ] **High**: **⚠️ Schema gap NOW FIXED** — The prior report's two 🔴 critical findings (`type` column and `node_links` DDL) have been resolved in the uncommitted working tree. This is a significant improvement. (Found in: unknown)
- [ ] **High**: **❌ `POST /sync/push` has no `requireApiKey`** — The legacy CQRS outbox receiver remains unauthenticated. Any client can send arbitrary L3 node creation events to the server without API key. This is a 🔴 security risk. (Found in: unknown)
- [ ] **High**: **🔴 `POST /sync/push` unauthenticated** — No `requireApiKey` middleware. The endpoint accepts CQRS outbox events and writes directly to the database without any authentication. This is exploitable for unauthorized data injection. (Found in: unknown)
- [ ] **High**: **🔴 `POST /sync/push` unauthenticated** — The legacy CQRS outbox receiver at `artifacts/api-server/src/routes/sync.ts:14` has no `requireApiKey` middleware. This allows unauthenticated L3 node creation. **Recommendation:** Add `requireApiKey` to the router or remove the endpoint if `POST /projects/:id/sync` fully supersedes it. (Found in: unknown)
- [ ] **High**: **🔴 `POST /sync/push` unauthenticated** — Legacy CQRS outbox receiver at `artifacts/api-server/src/routes/sync.ts:14` has no `requireApiKey` middleware. **Recommendation:** Add `requireApiKey` to the router mount or remove the endpoint. (Found in: unknown)
