# Verification Report: 3.2.2 — Decay application on knowledge query results

**Item ID:** 3.2.2
**Description:** Decay application on knowledge query results
**Date:** 2026-06-13
**Verdict:** ⚠️ WARN

## Team Review (Architecture & SRE)
- **Leo (Architect)**: Applying `EXP()` math with `NOW()` inside the SQL query seemed elegant for temporal decay.
- **Max (SRE / Security)**: Dynamic math against `NOW()` in `ORDER BY` completely breaks indexing, causing full table scans and crushing DB performance. Decay must be applied post-fetch in memory (for small N) or pre-calculated.
- **Conclusion**: Performance mandated change (Post-fetch application or trigram pre-filtering).
