## Round 1 — Architecture & Design Review

### Design Spec Summary (ADR-010)

ADR-010 specifies that after the bootstrap phase:
1. L2 module boundaries are written as **glob path patterns** to `.docuvia/config.yaml` under `modules:`.
2. All future commits are assigned to L2 modules **deterministically by path matching** — the LLM is no longer used for L2 assignment.
3. Historical `commit_l2_links` rows are flagged with `reindexRequired: true` and retroactively corrected on the next generate run.

### Findings

**✅ Schema is complete.** The `l2_nodes` table has all required columns:
- `pathPatterns` (jsonb) — stores glob path patterns
- `reindexRequired` (boolean) — flags nodes needing reindexing
- `isBootstrapConfirmed` (boolean) — indicates bootstrap completion

The `commit_l2_links` junction table exists with proper foreign keys, unique constraint, and indexes. The `commits.l2NodeId` column is correctly marked `@deprecated`.

**✅ Bootstrap detection logic exists.** In `generate.ts` (lines 722–731), the code checks `allBootstrapConfirmed` — if all L2 nodes for a project have `isBootstrapConfirmed = true`, the generate pipeline skips L2 extraction and logs "path-rule mode; L2 assignment deferred to sync pipeline".

**❌ CRITICAL: No deterministic commit-to-module assignment logic exists.** The path-rule mode in `generate.ts` is a no-op. When `allBootstrapConfirmed` is true, the code (lines 727–731) only logs a message and sets `l2Input` to an empty array. No commits are processed, no path matching occurs, no `commit_l2_links` rows are created. The feature is fundamentally unimplemented.

**❌ CRITICAL: Diff paths are never extracted or stored.** The ingestion pipeline (`ingestion-pipeline.ts`) stores commit diffs as raw text but never parses the file paths from the diff output. The `commit_l2_links` table has a `diffPaths` JSONB column that could store this data, but it is never populated. Without file paths, there is nothing to match glob patterns against.

**❌ Path matching uses `startsWith()` instead of glob matching.** The `runSieveModel` function in `generate.ts` (lines 426–431) and its duplicates in `test-sieve.ts` (lines 47–52) and `test-output.ts` (lines 423–428) all use:
```typescript
patterns.some((p: string) => sourceFile.startsWith(p) || sourceFile === p)
```
This is a simple prefix check, NOT glob matching. A pattern like `src/**/utils/*.ts` would not work. This contradicts the ADR's explicit requirement for "glob path patterns".

**⚠️ Glob matching exists only in VS Code client.** The `DocuviaCodeLensProvider.ts` (line 65) correctly uses `minimatch(relPath, pattern, { matchBase: true })` for glob matching. This proves the team has the knowledge and tooling, but it was not applied to the server-side commit assignment logic.

**⚠️ No `.docuvia/config.yaml` module pattern reading.** There is no code that reads the `modules:` section from `.docuvia/config.yaml` and uses it for server-side commit assignment. The `orphan-branch-writer.ts` writes `path_patterns` to the orphan branch YAML, but nothing reads them back for assignment purposes.

## Round 2 — Code Quality & Security Review

### Code Smells and Anti-Patterns

1. **Duplicated `runSieveModel` logic.** The sieve model path-matching code is duplicated in three files: `generate.ts`, `test-sieve.ts`, and `test-output.ts`. All three use the same flawed `startsWith()` approach instead of proper glob matching. This violates DRY and means any fix needs to be applied in three places.

2. **Dead code path.** The `allBootstrapConfirmed` branch in `generate.ts` (lines 727–731) produces an empty `l2Input` array, which means the entire L2/L3 processing loop (lines 757–951) is skipped. This leaves commits unprocessed with no fallback — a silent failure mode.

3. **Inconsistent path matching strategies.** The VS Code client uses `minimatch` (proper glob), while the server uses `startsWith()` (prefix-only). This inconsistency will cause confusion: a pattern like `*.test.ts` would work in the VS Code CodeLens but fail in the server-side sieve model.

4. **`commitL2LinksTable` queried by wrong column in test files.** In `test-sieve.ts` (line 31) and `test-output.ts` (line 407), the code queries `commitL2LinksTable.commitHash`, but the schema defines `commitId` (integer), not `commitHash` (text). The correct query in `generate.ts` (line 409) uses `commitL2LinksTable.commitId`. This would cause runtime errors in the test files.

### Security

No specific security vulnerabilities identified for this feature. The path matching operates on internal data (commit diff paths) rather than direct user input.

## Round 3 — Integration & Completeness Review

### Integration Gaps

1. **Generate pipeline ↔ Path-rule mode.** The generate endpoint has two modes (bootstrap and path-rule) but the path-rule mode is non-functional. After a project manager confirms the L2 module map, the generate pipeline will stop processing commits entirely with no alternative assignment mechanism.

2. **Ingestion ↔ Path assignment.** The ingestion pipeline stores commit diffs but doesn't extract file paths. Even if path-rule matching were implemented, there would be no file path data to match against.

3. **Sync endpoint ↔ Path assignment.** The `sync.ts` endpoint handles branch validity promotion but does not perform path-based commit-to-L2 assignment. The generate.ts log message says "L2 assignment deferred to sync pipeline" but sync.ts has no such logic.

4. **Orphan branch writer.** The `orphan-branch-writer.ts` correctly serializes `pathPatterns` to YAML, but nothing consumes this data for server-side assignment.

### Missing Pieces for Completeness

To fully implement item 4.2.5, the following are needed:

1. **Diff path extraction.** Parse file paths from commit diffs during ingestion and store them in `commit_l2_links.diffPaths` (or a similar structure).

2. **Glob matching function.** Replace `startsWith()` with proper glob matching using `minimatch` (already a dependency in the VS Code client; needs to be added to the API server).

3. **Path-rule assignment logic.** Implement the actual commit-to-L2-module assignment in either the generate pipeline or the sync endpoint, using the glob patterns from `l2_nodes.pathPatterns`.

4. **Retroactive reindexing.** When `reindexRequired` is true, re-assign historical commits using the new path rules.

5. **Config YAML integration.** Read path patterns from `.docuvia/config.yaml` modules section (or from the database `l2_nodes.pathPatterns` column) and apply them during generate.

### Tests

No tests exist for the path-rule matching logic. The `test-sieve.ts` and `test-output.ts` files contain duplicated sieve model code but are not part of the test suite (no `.test.ts` suffix). There are no unit tests for glob-based commit-to-module assignment.

## Overall Verdict

### ❌ FAIL

**Reason:** The core feature — deterministic commit-to-module assignment via glob matching — is not implemented. The database schema is ready, and the bootstrap detection logic exists, but:

1. The path-rule mode in `generate.ts` is a no-op that skips all commit processing.
2. No code extracts file paths from commit diffs (required for any path matching).
3. The existing path "matching" in `runSieveModel` uses `startsWith()` instead of glob matching, which does not support the glob patterns specified in ADR-010.
4. The `commit_l2_links` table's `diffPaths` column is never populated.
5. There are no tests for this feature.

**The feature is architecturally scaffolded but functionally incomplete.** The schema, bootstrap detection, and orphan branch serialization are in place, but the actual assignment engine — the core of this feature — is missing.

---

## Recommendations

1. **Implement diff path extraction** in `ingestion-pipeline.ts` — parse `git diff --name-only` output or extract paths from diff headers, and store them in `commit_l2_links.diffPaths`.

2. **Add `minimatch` to the API server** and create a shared utility function for glob-based path matching, replacing the `startsWith()` calls in `generate.ts`, `test-sieve.ts`, and `test-output.ts`.

3. **Implement the path-rule assignment** in the generate pipeline's `allBootstrapConfirmed` branch — iterate over unprocessed commits, match their diff paths against `l2_nodes.pathPatterns`, and create `commit_l2_links` entries.

4. **Fix the `commitId` vs `commitHash` bug** in `test-sieve.ts` and `test-output.ts` (line 31/407) — the schema uses `commitId` (integer), not `commitHash`.

5. **Add unit tests** for the glob matching function and the path-rule assignment logic.
