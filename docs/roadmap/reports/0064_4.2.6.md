## Round 1 — Architecture & Design Review

### What the Design Spec Requires

ADR-010 specifies a migration from a single `commits.l2NodeId` foreign key (one-to-many: one commit → one L2 module) to a `commit_l2_links` junction table (many-to-many: one commit → multiple L2 modules). The spec says:

1. Create `commit_l2_links` junction table ✅
2. Deprecate `commits.l2NodeId` — set nullable, stop writing, remove in v3 ⚠️ PARTIAL
3. Use `commit_l2_links` for all new commit→L2 associations ✅
4. Support retroactive reindexing via `reindexRequired` flag on `l2_nodes` ✅ (schema only)

### Schema Design Assessment

The `commit_l2_links` table (`commit_l2_links.ts:15-33`) is well-designed:
- Proper foreign keys with `ON DELETE CASCADE` on both `commitId` and `l2NodeId`
- Unique constraint on `(commitId, l2NodeId)` prevents duplicate links
- Indexes on both foreign key columns for efficient lookups in both directions
- `diffPaths` JSONB column for storing file paths from commit diffs
- Zod insert schema auto-generated via `drizzle-zod`

The `commits.ts` table correctly marks `l2NodeId` as `@deprecated` with a comment explaining the v2→v3 migration path. The column is nullable (no `.notNull()`), which is correct for a deprecated column.

The `l2_nodes.ts` table has all required columns: `pathPatterns` (JSONB), `reindexRequired` (boolean, default false), `isBootstrapConfirmed` (boolean, default false).

### Gap: Deprecated Column Still Actively Written

**This is the most significant architectural gap.** At `generate.ts:938-947`, the generate pipeline writes to BOTH the deprecated column AND the new junction table:

```typescript
// Line 938-941: Still writing to deprecated column
await db
  .update(commitsTable)
  .set({ l2NodeId: l2node.id })
  .where(eq(commitsTable.id, commitId))
  .catch(() => {});
// Line 943-947: Also writing to new junction table
await db
  .insert(commitL2LinksTable)
  .values({ commitId, l2NodeId: l2node.id })
  .catch(() => {});
```

The ADR says "stop writing" to `commits.l2NodeId`. The code writes to both, creating dual maintenance. The `.catch(() => {})` on both calls silently swallows errors, meaning if the junction table insert fails, the deprecated column still gets updated — the system silently falls back to the old model.

### Gap: No Path-Rule Assignment in Sync Pipeline

When `allBootstrapConfirmed` is true (path-rule mode), `generate.ts:727-731` logs "L2 assignment deferred to sync pipeline" and sets `l2Input` to empty. However, the sync pipeline (`sync.ts`) has NO logic to match commit diff paths against `l2_nodes.pathPatterns` and create `commit_l2_links` entries. The sync endpoint only:
1. Upserts `llm_configs` from configYaml
2. Updates `commits.branchName`
3. Promotes validity on main branch
4. Checks autoGenerate cooldown
5. Writes to orphan branch

There is no code that reads `l2_nodes.pathPatterns`, matches them against pushed commit diffs, and inserts into `commit_l2_links`. This means path-rule mode is non-functional.

### Gap: `diffPaths` Column Never Populated

The `commit_l2_links.diffPaths` JSONB column exists in the schema but is never populated by any code. The generate pipeline inserts `{ commitId, l2NodeId }` but never sets `diffPaths`. The ingestion pipeline (`ingestion-pipeline.ts`) stores commit diffs as raw text but never parses file paths from diff output.

## Round 2 — Code Quality & Security Review

### Schema Quality

The `commit_l2_links.ts` schema is clean and follows project conventions:
- Uses `serial` for primary key (consistent with other tables)
- Proper `pgTable` declaration with typed columns
- Unique constraint and indexes defined in the table callback
- Zod schema auto-generated via `drizzle-zod` with proper `.omit()` for auto-generated fields
- Type exports for `InsertCommitL2Link` and `CommitL2Link`

### Code Smell: Dual Writes to Deprecated and New Columns

At `generate.ts:938-947`, writing to both `commits.l2NodeId` (deprecated) and `commit_l2_links` (new) is an anti-pattern. The deprecated write should be removed entirely. The `.catch(() => {})` pattern on both calls is also problematic — it silently swallows all errors including constraint violations, making debugging difficult.

### Code Smell: Silent Error Swallowing

Both the deprecated column update and the junction table insert use `.catch(() => {})`. This means:
- Unique constraint violations on the junction table are silently ignored
- Foreign key violations are silently ignored
- The deprecated column update could succeed while the junction table insert fails, leaving the system in an inconsistent state

### Missing Input Validation

The `commit_l2_links` table has no application-level validation beyond the Zod schema. The `insertCommitL2LinkSchema` is generated but never used in the generate pipeline — the insert at line 944-947 uses raw `.values()` without schema validation.

### No Migration File

There is no SQL migration file for the `commit_l2_links` table. The project uses `pnpm --filter @workspace/db run push` (Drizzle push), which applies schema changes directly. While this is the project's documented workflow, it means there is no versioned migration artifact for this structural change.

## Round 3 — Integration & Completeness Review

### Integration with Generate Pipeline

The `commit_l2_links` table is used in the generate pipeline at two points:
1. **Write path** (`generate.ts:938-947`): Inserts into `commit_l2_links` when processing L3 nodes with commit hashes. Also writes to deprecated `commits.l2NodeId`.
2. **Read path** (`generate.ts:407-411`): The Sieve Model reads `commit_l2_links` to find L2 nodes linked to a commit (GitHistory signal).

The Sieve Model integration is well-designed — it queries the junction table by `commitId` and uses the results as a signal (W1 = 0.3) in the scoring algorithm.

### Integration with Sync Pipeline

The sync pipeline (`sync.ts:156-163`) reads `commit_l2_links` to find L2 nodes linked to pushed commits, then cascades validity status to L3 nodes under those L2 nodes. This is a correct use of the junction table.

### Missing: Path-Rule Mode End-to-End

The complete path-rule flow is:
1. Bootstrap mode discovers L2 modules via AI ✅ (implemented in generate.ts:733-754)
2. Human confirms module map ❌ (no confirmation endpoint exists)
3. Path patterns stored in `l2_nodes.pathPatterns` ❌ (no code writes to this column)
4. Future commits assigned via path matching ❌ (no code in sync pipeline)
5. Historical `commit_l2_links` flagged with `reindexRequired` ❌ (no code sets this)

Steps 2-5 are completely unimplemented. The schema columns exist but no code populates or uses them for path-rule mode.

### Missing: Reindex Mechanism

ADR-010 states: "Historical `commit_l2_links` rows are flagged with `reindexRequired: true` and retroactively corrected on the next generate run." The `reindexRequired` column exists on `l2_nodes.ts:23` but:
- No code ever sets `reindexRequired = true`
- No generate pipeline logic checks `reindexRequired` and reprocesses historical links

### Missing: API Endpoints for commit_l2_links

There are no REST API endpoints for querying or managing `commit_l2_links`. The table is only accessed internally by the generate and sync pipelines. This is acceptable for an internal junction table but means there's no way to inspect or debug the table via API.

## Findings

### 🔴 HIGH-1: Deprecated `commits.l2NodeId` Column Still Actively Written

**Location:** `artifacts/api-server/src/routes/generate.ts:938-941`
**Issue:** The generate pipeline writes to the deprecated `commits.l2NodeId` column on every L3 node processing iteration. ADR-010 says "stop writing" to this column. The dual-write pattern means the deprecated column is kept in sync with the junction table, making it impossible to remove the column in v3 without breaking backward compatibility.
**Recommendation:** Remove the `commitsTable.update()` call at line 938-941. Only write to `commitL2LinksTable`.

### 🔴 HIGH-2: No Path-Rule Assignment Logic in Sync Pipeline

**Location:** `artifacts/api-server/src/routes/sync.ts` (entire file)
**Issue:** When all L2 nodes are bootstrap-confirmed, the generate pipeline defers L2 assignment to the sync pipeline. But the sync pipeline has no path-matching logic. The `commit_l2_links` table's `diffPaths` column is never populated, and `l2_nodes.pathPatterns` is never read.
**Recommendation:** Implement path-rule matching in the sync endpoint: read `l2_nodes.pathPatterns` for the project, extract file paths from pushed commit diffs, match using glob patterns (e.g., `minimatch`), and insert into `commit_l2_links`.

### 🟡 MEDIUM-1: `diffPaths` Column Never Populated

**Location:** `lib/db/src/schema/commit_l2_links.ts:25`
**Issue:** The `diffPaths` JSONB column is defined but never written to. This column is needed for path-rule matching and for debugging which files caused a commit→L2 link.
**Recommendation:** Parse file paths from commit diffs during ingestion and store them in `commit_l2_links.diffPaths` when creating links.

### 🟡 MEDIUM-2: No Bootstrap Confirmation Endpoint

**Location:** No `POST /projects/:id/l2-nodes/confirm-bootstrap` endpoint exists
**Issue:** ADR-010 requires a human confirmation step after bootstrap discovery. No endpoint exists to accept the confirmed module map, set `isBootstrapConfirmed = true`, store `pathPatterns`, or set `reindexRequired = true`.
**Recommendation:** Implement the bootstrap confirmation endpoint that accepts the confirmed module map with path patterns.

### 🟡 MEDIUM-3: Silent Error Swallowing on Junction Table Operations

**Location:** `artifacts/api-server/src/routes/generate.ts:941, 947`
**Issue:** Both the deprecated column update and the junction table insert use `.catch(() => {})`, silently swallowing all errors. This makes debugging impossible and can leave the system in an inconsistent state.
**Recommendation:** At minimum, log errors at warn level. Ideally, the junction table insert should be the primary operation with proper error handling.

### 🟢 LOW-1: No Migration File for Junction Table

**Issue:** The `commit_l2_links` table is only defined in the Drizzle schema with no corresponding SQL migration file. While the project uses Drizzle push, a migration file would provide better auditability.
**Recommendation:** Consider generating a Drizzle migration (`drizzle-kit generate`) for this structural change.

### 🟢 LOW-2: `insertCommitL2LinkSchema` Not Used in Generate Pipeline

**Location:** `artifacts/api-server/src/routes/generate.ts:944-947`
**Issue:** The Zod insert schema is generated at `commit_l2_links.ts:35-38` but never used in the generate pipeline. The insert uses raw `.values()` without validation.
**Recommendation:** Validate insert payloads against `insertCommitL2LinkSchema` before inserting.

---

## Overall Verdict: ⚠️ WARN

**Summary:** The `commit_l2_links` junction table is properly defined in the schema with correct constraints, indexes, and types. It is correctly integrated into the generate pipeline (write path) and sync pipeline (read path). The Sieve Model correctly uses it for GitHistory signal scoring.

However, there are significant gaps:

1. **The deprecated `commits.l2NodeId` column is still actively written to**, violating the ADR-010 deprecation directive.
2. **Path-rule mode is completely non-functional** — the sync pipeline has no path-matching logic, the bootstrap confirmation endpoint doesn't exist, and the `diffPaths` column is never populated.
3. **The reindex mechanism is unimplemented** — `reindexRequired` is never set and never checked.

The schema foundation is solid, but the implementation is incomplete. The junction table exists and is used for bootstrap-mode AI discovery, but the transition to deterministic path-rule mode (the core value proposition of ADR-010) is not implemented.
