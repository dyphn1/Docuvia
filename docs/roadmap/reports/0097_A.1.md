# Verification Report: A.1 — `docuvia impact <target>` CLI command

**Item ID:** A.1
**Description:** `docuvia impact <target>` CLI command — expose the already-built, already-tested `QueryService.getImpact()` (used internally by `docuvia review` and the `docuvia_impact` MCP tool) as a standalone by-symbol command.
**Date: 2026-07-11**
**Verdict:** PASS

## Implementation Details

- Plan followed: `docs/ai_plans/implement_docuvia_impact_command.md`, implemented in full, no design deviations.

- Shared risk-threshold extraction — `lib/core/src/services/change-detection-service.ts`: extracted the inline LOW/MEDIUM/HIGH/CRITICAL if/else chain out of `detectChanges()` into a new exported pure function `computeImpactRiskLevel(impactedCount: number): RiskLevel`, built on the existing (now exported) `IMPACT_RISK_THRESHOLDS` (`HIGH_MIN: 6`, `CRITICAL_MIN: 21`). `detectChanges()` now calls `computeImpactRiskLevel(totalImpacted)` and then applies its own review-specific "large diff floor" LOW to MEDIUM bump (`filesChanged.length > 10`) on top, exactly as before — the bump was deliberately kept out of the shared function per the plan, since it is diff-size-driven and does not apply to a single-symbol `impact` query.

- New log file constant — `lib/core/src/constants/paths.ts`: added `IMPACT_LOG_FILE_NAME = "impact.log"` alongside the other 8 one-shot-command log file names.

- New CLI command file — `artifacts/cli/src/commands/impact.ts`: `impactCommand(target, { escalateToLsp }, workspaceRoot)`, modeled on `query.ts` structure. Resolves `QueryService` via `resolveConfiguredService`, calls `queryService.getImpact(target, escalateToLsp)`, and:
  - prints a not-found warning (spinner `.warn()`) when the target does not resolve to a graph node,
  - otherwise prints the blast-radius entries (`name (type)` per line) plus the risk level computed via the shared `computeImpactRiskLevel()`, color-coded the same way `review.ts` colors its risk line (`ui.error` for CRITICAL, `ui.warn` for HIGH, plain `console.log` otherwise),
  - wraps the whole call in start/summary/error JSONL logging via `appendCommandLogLine(workspaceRoot, IMPACT_LOG_FILE_NAME, ...)`, each wrapped in `.catch(() => {})` so a logging failure never fails the command — the same isolation pattern used by all 8 other one-shot commands.
  - Missing target and a thrown error from `getImpact()` both exit with `process.exit(1)`, mirroring `query.ts` error-handling convention.

- CLI wiring:
  - `artifacts/cli/src/constants/cli-commands.ts`: added `IMPACT: "impact"` to `CLI_COMMANDS`, a `CLI_COMMAND_DESCRIPTIONS` entry (Get blast radius for a symbol), and a `getUsageText()` line.
  - `artifacts/cli/src/constants/cli-flags.ts`: added `ESCALATE_TO_LSP: "--escalateToLsp"` to `CLI_FLAGS`.
  - `artifacts/cli/src/constants/ui-messages.ts`: added the IMPACT message block (header, start/success/not-found/fail text, blast-radius header, no-dependents text, risk-level prefix).
  - `artifacts/cli/src/cli.ts`: added `handleImpact()` (mirrors `handleQuery()`, threading the `--escalateToLsp` flag), registered it in `COMMAND_HANDLERS`. No change needed to the interactive command-selection menu filter — it already only excludes MCP and EXPORT, so impact appears in the wizard menu automatically via the existing `Object.values(CLI_COMMANDS)` iteration.
  - No change needed to `artifacts/cli/src/di.ts` — `QueryService` was already registered under `DI_TOKENS.QueryService`.

- `getImpact()` itself is unchanged — no signature change, no double-logging: the log-writer calls live in the CLI command (`impact.ts`), not inside `QueryService.getImpact()`, since that method is also called by `ChangeDetectionService.detectChanges()` (which already logs its own review.start/review.summary at the review level) and the `docuvia_impact` MCP tool (which does not use the JSONL log-writer pattern at all).
