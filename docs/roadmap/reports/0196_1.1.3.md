## Round 1 — Architecture & Design Review

### Design Document Accuracy

The design document `10-quality-requirements.md` Section 10.2.3 states:

> **Test isolation** — DB state must not leak between tests — `withRollback()` from `artifacts/api-server/test/support/db.ts` wraps all DB-backed integration tests

This requirement remains correctly implemented. The `withRollback()` function exists at the specified path and is used by both integration tests.

### Implementation Architecture Analysis

The `runInRollbackTransaction` implementation (`lib/db/src/index.ts` lines 42-60) is unchanged since the previous verification. It continues to use:

1. **AsyncLocalStorage context propagation** — `transactionStore.run()` ensures the `db` Proxy object automatically uses the transaction connection during the callback.
2. **RollbackSignal pattern** — A special error thrown after successfulcallback completion, caught by the outer catch block to return the value.
3. **Transaction guaranteed rollback** — Since `RollbackSignal` is thrown inside `baseDb.transaction()`, PostgreSQL automatically rolls back.

### Changes Since Previous Verification (2026-06-08)

**Significant improvements found:**

1. **`vitest.config.ts`** — The `include` pattern was expanded from `["artifacts/*/test/**/*.test.ts", "lib/**/*.unit.test.ts"]` to also include `"artifacts/*/src/**/*.unit.test.ts"`. This enables the colocated unit test pattern described in the design doc's "Test discoverability" rule (10.2.3). Coverage configuration was also added with proper exclude patterns for generated code.

2. **`factories.ts`** — Significantly updated:
   - Now imports table objects directly (`projectsTable`, `l2NodesTable`, etc.) instead of relying on model type imports
   - Added `ActivityLogFactory` with `build` and `create` methods
   - Uses `getDb(client)` helper for transaction context support (line 18: `const getDb = (client?: any) => client ?? db`)
   - This is a proper expansion supporting more test scenarios

3. **New integration test: `generate.test.ts`** — Tests the `POST /api/projects/:id/generate` endpoint. Uses `withRollback()` correctly (the entire test body is wrapped). Tests both the API response shape and the database state changes (verifying project status, L1 tags, L2 nodes, L3 nodes were created). Uses the `ProjectFactory` and `CommitFactory` from the test factories.

4. **New unit tests (3 files)**:
   - `decay.unit.test.ts` — Tests `calculateTemporalDecay` for current dates, future date clamping, and 14-day half-life decay
   - `intent-router.unit.test.ts` — Tests `escapeLike` (SQL LIKE escaping), `calculateTemporalDecay` (half-life math), and `sanitizeQuery` (control char removal, truncation, trimming)
   - `embedding.unit.test.ts` — Tests `cosinitySimilarity` (identical, orthogonal, opposite, empty, different-length, zero-magnitude vectors) and `parseEmbedding` (valid JSON, invalid, nullish, non-array, empty array)

5. **MSW handlers restructured** — The `handlers.ts` file now imports and spreads `openaiHandlers` from a separate `handlers/openai.ts` file. The OpenAI handler in `openai.ts` provides context-aware responses based on message content (L1 tag generation, L2/L3 node generation, content synthesis, architecture extraction). This is well-structured for maintainability.
