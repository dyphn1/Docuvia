## Round 1 — Architecture & Design Review

**What exists:**

The Drizzle ORM schema correctly implements all 19 tables as specified in the design documents. Every table from the section 5.4 table in `05-building-blocks.md` has a corresponding TypeScript schema file, and all are exported from `index.ts`.

**ADR Compliance:**

- **ADR-003 (Three-Tier Knowledge Graph):** L1 tags, L2 nodes, and L3 nodes are properly implemented with correct hierarchical relationships. L2 nodes reference projects; L3 nodes reference L2 nodes. The `node_links` table provides directed relationships.
- **ADR-009 (L3 Semantic Deduplication):** `l3_nodes` includes `occurrenceCount` (integer, default 1), `introducedInCommit` (text), `verifiedUntilCommit` (text), and `validityStatus` (text, default "pending"). The temporal range anchors have replaced the old `sourceCommits` JSONB approach. The `llm_configs` table includes `similarityThreshold` (real, default 0.85) and `condensationThreshold` (integer, default 30).
- **ADR-010 (L2 Bootstrap):** `l2_nodes` includes `pathPatterns` (jsonb), `reindexRequired` (boolean), and `isBootstrapConfirmed` (boolean). The `commit_l2_links` junction table exists with `commitId` FK (not commitHash), and `commits.l2NodeId` is properly marked as `@deprecated`.
- **ADR-011 (Two-Phase Knowledge Validity):** `l3_nodes` has `validityStatus` (text, default "pending"). `commits` has both `branchName` (text) and `validityStatus` (text, default "pending").
- **ADR-012 (Document Misc Pool):** `documents.projectId` is nullable (no `.notNull()`), enabling the misc pool. The table includes `contentHash` (text), `affiliatedAt` (timestamp), and `status` (text, default "unaffiliated").

**Architecture assessment:**

- ✅ All 19 tables implemented and exported
- ✅ Three-Tier Knowledge Structure (L1→L2→L3) properly enforced via foreign keys
- ✅ Referential integrity: all foreign keys use appropriate ON DELETE CASCADE/SET NULL
- ✅ PostgreSQL enums used for categorical data (project_status, vcs_type, l2_node_type, l3_node_type, review_entity_type, review_task_type, review_status, job_status, etc.)
- ✅ Timestamp tracking: createdAt/updatedAt/defaultNow() patterns consistently applied
- ✅ ADR-009/010/011/012 column requirements all satisfied
- ✅ Deprecated fields preserved with comments for backward compatibility

## Round 2 — Code Quality & Security Review

**Positive findings:**

1. **Consistent schema patterns:** All 19 tables follow the same structural conventions — import from drizzle-orm/pg-core, define enums where appropriate, use `pgTable` with typed column names, define `createInsertSchema` with auto-field omission, and export TypeScript types.
2. **Referential integrity:** Foreign keys specify ON DELETE CASCADE for required child records and SET NULL for optional links. The `subscriptions` table adds a unique constraint on `(subscriberProjectId, publisherProjectId)` to prevent duplicates.
3. **Data validation:** Sensible defaults throughout (e.g., `status: "pending"`, `occurrenceCount: 1`, `similarityThreshold: 0.85`). NotNull constraints on critical fields.
4. **Security:** No raw SQL in schema definitions. FK constraints prevent orphaned records. Zod schemas generated via drizzle-zod for runtime validation at the API layer.
5. **Code organization:** Clean barrel export in `index.ts`. Consistent formatting. Clear `@deprecated` comments on legacy fields.

**Issues identified:**

1. **🟡 Low — `job_queue.ts` inconsistent typing pattern:** Lines 21-22 use `$inferInsert` directly instead of `z.infer<typeof insertJobQueueSchema>`. Every other table that exports types uses `z.infer`. This is a minor code smell but does not affect functionality.
   ```typescript
   // job_queue.ts (line 21-22)
   export type JobQueue = typeof jobQueueTable.$inferSelect;
   export type InsertJobQueue = typeof jobQueueTable.$inferInsert;  // inconsistent: no z.infer
   ```

2. **🟡 Low — `error_reports.ts` missing TypeScript type exports:** The file does not export `ErrorReport` or `InsertErrorReport` types. Line 18 defines `insertErrorReportSchema` but no corresponding `z.infer` type export. This means consumers must use `$inferSelect`/`$inferInsert` directly.
   ```typescript
   // error_reports.ts — missing:
   // export type ErrorReport = typeof errorReportsTable.$inferSelect;
   // export type InsertErrorReport = z.infer<typeof insertErrorReportSchema>;
   ```

3. **🟢 Very Low — `correction_examples.ts` missing update schema:** Most tables export an `updateSchema` (via `insertSchema.partial()`), but `correction_examples.ts` does not. This is a minor inconsistency in the API surface.

4. **🟢 Very Low — `documents.ts` formatting:** Line 24 (`contentHash`) has a different indentation (4 spaces vs aligned `:`) compared to surrounding lines. Trivial style issue.
