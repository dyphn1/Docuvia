## Round 1 — Architecture & Design Review

### What the Design Specifies (ADR-002)

The "Local-First, Server-Augmented" architecture defines three tiers of operation:

1. **Standalone Mode** (no server): Depth-2 topology scanning, `git log -n 100`, Keyword RAG and Direct Anchoring using `target_refs`, local garbage collection based on `last_verified_at` decay
2. **Server-Augmented Mode** (with server): Full 4-way Agentic RAG, vector/graph traversal, async swarm evolution
3. **Offline Writes & Sync Outbox (CQRS)**: Local SQLite writes, SyncOutbox queue, server gatekeeper with mutex lock, local rehydration via git fetch/merge

The `KnowledgeStore._loadWorkspace()` method implements a three-tier data loading fallback:
- **Tier 1**: Server API (`pullSnapshot()`)
- **Tier 2**: Local `.docuvia/` files
- **Tier 3**: Git orphan branch (`docuvia-knowledge`)

### What Is Implemented (Current State)

**Three-tier fallback chain (KnowledgeStore.ts, lines 122–225):**
- ✅ **Tier 1 (Server API)**: Correctly implemented. `CentralServerClient.pullSnapshot()` calls `GET /projects/{id}/graph`. Failure is caught and triggers Tier 2.
- ✅ **Tier 2 (Local files)**: Correctly implemented. Reads `l1_tags.yaml`, `l2_modules.yaml`, `l3_router.yaml`, and `l3_decisions/*.md` from `.docuvia/` directory.
- ✅ **Tier 3 (Git fallback)**: Correctly implemented. Uses `git ls-tree` and `git cat-file --batch` to read knowledge files from the `docuvia-knowledge` orphan branch.
- ✅ **`isServerConfigured()` guard**: `CentralServerClient.query()` (line 58–61) and `sync()` (line 104–105) return early when `server_url` is not configured.
- ✅ **Extension activation**: `activate()` (extension.ts lines 44–47) creates `CentralServerClient` and calls `setCentralClient()` regardless of server configuration.

**KnowledgeIndexer enhancements (NEW since last report):**
The `KnowledgeIndexer` has been significantly upgraded from a basic snapshot reader to a full offline indexing engine:
- ✅ **IntervalTree-based line anchoring** (KnowledgeIndexer.ts + IntervalTree.ts): L3 decisions are now mapped to line ranges using an augmented interval tree, enabling O(log N) lookup of decisions by line number. This is a major improvement for offline CodeLens and Hover accuracy.
- ✅ **Live document change tracking** (KnowledgeIndexer.ts, lines 150–166): The `onDidChangeTextDocument` handler shifts interval ranges as code is edited, keeping L3 decision anchors in sync with the user's code changes without requiring a full re-index.
- ✅ **Symbol-based matching** (KnowledgeIndexer.ts, lines 108–142): Uses `vscode.executeDocumentSymbolProvider` to match L3 decisions to code symbols (functions, classes) by name similarity, providing more accurate anchoring than the previous regex-only approach.
- ✅ **Save-triggered re-indexing** (KnowledgeIndexer.ts, lines 168–172): Full tree rebuild on file save ensures consistency after significant changes.

**DocuviaHoverProvider integration:**
- ✅ The hover provider (DocuviaHoverProvider.ts) now uses the `KnowledgeIndexer.getMatchAt()` method for line-accurate L3 decision lookup, replacing the previous snapshot-only approach. This means hover previews work correctly even as code is edited offline.

**DocuviaCodeLensProvider offline fallback:**
- ✅ The CodeLens provider (DocuviaCodeLensProvider.ts, lines 185–201) implements an offline fallback using manifest path patterns when server modules have no `source_paths`. This shows "connect to server for decisions" in offline mode, which is appropriate graceful degradation.

### Gaps Between Design and Implementation

1. ⚠️ **Missing: Offline writes / Sync Outbox (CQRS)**: ADR-002 describes a full CQRS pattern with local SQLite writes and a SyncOutbox. This is **not implemented**. The `addDecision` command (extension.ts line 159–162) is still commented out (`// await addDecision(context, store);`). The `addDecisionFromSelection` command (line 264–275) is also commented out. This is a significant gap vs. the ADR-002 design.

2. ⚠️ **Missing: `git log -n 100` topology scanning**: ADR-002 mentions "Depth-2 topology scanning and `git log -n 100`" as part of standalone mode. This is not implemented. The extension relies on pre-existing `.docuvia/` files or server data.

3. ⚠️ **Missing: `last_verified_at` decay / local garbage collection**: ADR-002 says "Local garbage collection based on `last_verified_at` decay" and notes "currently not implemented." This is still not implemented.

4. ℹ️ **ADR-002 acknowledges gaps**: The ADR itself notes `last_verified_at` is "currently not implemented" and the CQRS pattern is aspirational.

## Round 2 — Code Quality & Security Review

### Code Quality Findings

1. ✅ **Defensive design in KnowledgeStore**: The `load()` method uses a `_loading` flag (line 95–99) to prevent concurrent loads, with `_pendingReload` coalescing.

2. ✅ **Graceful error handling in fallback chain**: Each tier in `_loadWorkspace()` is wrapped in try/catch, with failures logged to the output channel without crashing the extension.

3. ✅ **`readUriSafe` helper** (KnowledgeStore.ts, line 533–539): Returns empty string instead of throwing when files don't exist.

4. ✅ **`IDocuviaClient` interface** (types.ts, lines 15–18): Uses a structural interface to avoid circular imports and enable testing with mock clients.

5. ✅ **IntervalTree implementation is clean**: The `IntervalTree` class (IntervalTree.ts) is a well-structured augmented BST with `insert`, `search`, and `shiftRanges` operations. The `shiftRanges` method correctly handles three cases: intervals entirely after the shift point, intervals straddling the shift point, and intervals before the shift point.

6. ✅ **KnowledgeIndexer debouncing**: The `queueIndexing` method (line 44–53) uses a 500ms debounce via `setTimeout` to avoid rapid re-indexing during active editing.

7. ✅ **Document symbol caching in CodeLensProvider**: The `DocuviaCodeLensProvider` caches LSP symbol anchors in `documentAnchors` (line 89) and only falls back to regex on initial load, then triggers async anchor updates.

8. ⚠️ **KnowledgeIndexer queue uses `Set<string>` without cleanup on dispose**: The `_indexingQueue` Set (line 11) tracks pending indexing tasks but is never cleared in the `dispose()` method (line 174–176). If `dispose()` is called while a `setTimeout` is pending, the callback will still fire and call `buildTreeForFile` on a disposed indexer. This is a minor resource leak.

9. ⚠️ **`findBestSymbolMatch` has O(n×m) complexity**: The symbol matching (KnowledgeIndexer.ts, lines 108–142) traverses all symbols and for each, checks all query words. For files with many symbols and decisions with many words, this could be slow. However, for typical file sizes this is acceptable.

10. ⚠️ **`KnowledgeStore._loadWorkspace` is 103 lines**: This method handles manifest parsing, server API calls, local file reading, and git fallback all in one method. It could be decomposed into smaller methods for readability.

11. ℹ️ **Three different concurrency mechanisms in the broader codebase**: Advisory locks (sync.ts), optimistic locking (generate.ts), and in-memory booleans (metabolism.ts). Each is appropriate for its use case.

### Security Findings

1. ✅ **Path traversal protection in `initProject`** (extension.ts, lines 471–475): Validates `targetRoot` against path traversal using `path.relative()`.
2. ✅ **Token storage uses VS Code SecretStorage**: `CredentialManager` is initialized with `context.secrets` (extension.ts line 44).
3. ✅ **Token sent via `x-docuvia-token` header**: CentralServerClient attaches the token to all requests.
4. ✅ **GlobalConfig validates HTTPS**: `types.ts` line 62–64 enforces that `server_url` must start with `https://`.
5. ⚠️ **No input validation on `server_url` beyond HTTPS scheme**: No check against localhost or internal network URLs. This could be a concern in enterprise deployments.
6. ⚠️ **`git cat-file --batch` parsing complexity**: The `readGitBlobs` method (KnowledgeStore.ts, lines 348–425) implements a manual binary protocol parser. While careful (size validation, type checking), any subtle change in git's output format could silently break the fallback.

## Round 3 — Integration & Completeness Review

### Integration Findings

1. ✅ **CentralServerClient is optional**: The store works identically whether or not a `CentralServerClient` is set. The `setCentralClient()` call is always made, and `_loadWorkspace()` checks `this._client && this._client.isServerConfigured()` before attempting server calls.

2. ✅ **All UI components work offline**: `KnowledgeGraphTreeProvider`, `DocuviaCodeLensProvider`, and `DocuviaHoverProvider` all read from the `KnowledgeStore` snapshot, which is populated from local fallback even without a server.

3. ✅ **FileSystemWatcher reloads**: Changes to `.docuvia/` files trigger automatic reloads (KnowledgeStore.ts, lines 430–471), with debouncing and incremental vs. full reload logic.

4. ✅ **KnowledgeIndexer integrates with Hover and CodeLens**: The indexer is created in `extension.ts` (line 90) and passed to both the hover provider (line 95) and the CodeLens provider (via `updateSymbolAnchors` on save, line 99–103). The hover provider uses `getMatchAt()` for line-accurate decision lookup.

5. ✅ **Multi-workspace support**: The `load()` method iterates over all workspace folders (line 103–107), and `getSnapshotFor()` (lines 69–77) finds the correct snapshot by workspace folder URI.

6. ✅ **KnowledgeIndexer live update integration**: The `onDidChangeTextDocument` handler (KnowledgeIndexer.ts, lines 150–166) keeps the interval tree in sync with code changes, meaning hover and CodeLens remain accurate during editing without server interaction.

7. ⚠️ **Drag-and-drop writes to `.docuvia/` trigger reload but not server sync**: The `KnowledgeGraphTreeProvider.handleDrop()` (lines 44–81) writes to `l3_router.yaml` and calls `store.load()`, but does not queue any server sync event. This is consistent with the missing CQRS implementation.

### Completeness

1. ❌ **No tests for graceful degradation**: There are no unit tests that verify the fallback chain behavior (server fails → local fallback → git fallback). No mock client or scenario tests exist.
2. ⚠️ **No tests for `CentralServerClient`**: The `CentralServerClient` class has no unit tests.
3. ⚠️ **No tests for `KnowledgeIndexer`**: The new IntervalTree-based indexer has no tests. The `IntervalTree` data structure itself is untested.
4. ⚠️ **No tests for `IntervalTree`**: The `shiftRanges` operation (which is critical for live editing accuracy) has no test coverage.
5. ⚠️ **Extension test fixtures are minimal**: `tests/fixtures/empty-workspace/` contains only a `.vscode/settings.json`. No fixture for a workspace with `.docuvia/` files.

### Performance

1. ✅ **Snapshot caching**: KnowledgeStore keeps parsed snapshots in memory and only reloads on file changes.
2. ✅ **Debounced file watching**: Changes to `.docuvia/` files are debounced at 300ms.
3. ✅ **Incremental vs. full reload**: The `_handleBatchedChanges` method distinguishes between small changes (per-workspace reload) and large changes (full reload).
4. ✅ **IntervalTree provides O(log N) lookups**: The new interval tree implementation provides efficient line-range-to-decision mapping, a significant improvement over linear scanning.
5. ✅ **KnowledgeIndexer debouncing**: 500ms debounce on indexing prevents excessive re-indexing during active editing.

## Recommendations

1. **Implement the offline write path**: Either implement the CQRS Sync Outbox pattern as described in ADR-002, or update the ADR to reflect that offline writes are out of scope. The commented-out `addDecision` code should be completed or removed.

2. **Add integration tests for the fallback chain**: Create tests that mock `CentralServerClient` to simulate server failure and verify that KnowledgeStore correctly falls back to local files and then to the git orphan branch.

3. **Add unit tests for IntervalTree**: Test the `shiftRanges` operation thoroughly, as it is critical for live editing accuracy. Edge cases include: shifts at interval boundaries, overlapping intervals, and multiple sequential shifts.

4. **Add unit tests for KnowledgeIndexer**: Test the `getMatchAt` method with various interval configurations, and verify that `onDidChangeTextDocument` correctly shifts ranges.

5. **Fix the `dispose()` method**: Clear the `_indexingQueue` and cancel any pending `setTimeout` callbacks in `KnowledgeIndexer.dispose()`.

6. **Add a test fixture workspace with `.docuvia/` files**: Create a fixture directory with realistic `l1_tags.yaml`, `l2_modules.yaml`, `l3_router.yaml`, and `l3_decisions/` files.

## Overall Verdict

**⚠️ WARN**

The read-path graceful degradation in `CentralServerClient.ts` and `KnowledgeStore.ts` remains well-implemented with a clean three-tier fallback chain. The significant enhancement in commit `eba22d4` — the new IntervalTree-based KnowledgeIndexer with live document change tracking and symbol-based matching — substantially improves the offline experience by making CodeLens and Hover more accurate and responsive without server interaction. The `isServerConfigured()` guard correctly prevents server calls when no URL is configured, and all UI components function entirely from local snapshot data.

However, the write-path offline capability (CQRS/Sync Outbox) remains unimplemented, the `addDecision` and `addDecisionFromSelection` commands are still commented out, and there is zero test coverage for the fallback chain, the KnowledgeIndexer, or the IntervalTree. The verdict remains **⚠️ WARN**: the read-path works well and has been improved, but the write path and test coverage gaps persist.
