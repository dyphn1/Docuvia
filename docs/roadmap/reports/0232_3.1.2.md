## Round 1 — Architecture & Design Review

### What the Design Specifies

ADR-006 describes the few-shot injection as part of the Swarm Intelligence Pipeline (Stage 3 — Experience Rollout):

> "When a new developer queries the AI, the local router in `intent-router.ts` runs O(1) checks for `#attach` or specific domain keywords mapped from L1/L2 database names to pre-inject the guardrail natively."

The design intent is that correction examples captured from human reviews are fed back into the LLM generation prompts as few-shot examples, so the AI learns from past corrections and avoids repeating mistakes.

### Implementation Status

| Component                                 | Status             | Location                                                                                                                                                                                                                           |
| ----------------------------------------- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `getRecentCorrections()` function         | ✅ Implemented     | `generate.ts:88-104` — queries `correction_examples` table by `projectId` + `entityType`, ordered by `createdAt desc`, limited to 5                                                                                                |
| `buildFewShotSection()` function          | ✅ Implemented     | `generate.ts:106-117` — formats corrections into "Example N: Original: ... Corrected: ..." text                                                                                                                                    |
| Injection into L2 generation prompt       | ✅ Implemented     | `generate.ts:245` — `fewShotSection` appended to user message content in `generateL2Nodes()`                                                                                                                                       |
| Fetching corrections before L2 generation | ✅ Implemented     | `generate.ts:740` — `getRecentCorrections(projectId, "l2_node")` called before batch L2 generation loop                                                                                                                            |
| Injection into L3 generation              | ❌ Not implemented | L3 nodes are generated inside `generateL2Nodes()` as part of the same LLM call; no separate L3 few-shot injection exists                                                                                                           |
| Injection in path-rule mode               | ❌ Not implemented | When all L2 nodes are bootstrap-confirmed (`allBootstrapConfirmed === true`), the code takes the deterministic path-rule branch (`generate.ts:771-863`) which never calls `generateL2Nodes()`, so few-shot examples are never used |
| O(1) fast-path pre-injection              | ❌ Not implemented | No regex pre-filter or keyword-based guardrail injection exists in `intent-router.ts`                                                                                                                                              |

### Gaps Identified

1. **L3 corrections never injected**: The `getRecentCorrections()` function accepts `"l2_node" | "l3_node"` as the `entityType` parameter, but it is only ever called with `"l2_node"` at `generate.ts:740`. L3 corrections stored in the database are never fetched or injected as few-shot examples. This means the feedback loop for L3 corrections is broken at the injection stage (even though corrections are captured in `review_tasks.ts:158`).

2. **Few-shot injection skipped in path-rule mode**: When all L2 nodes are bootstrap-confirmed, the generate pipeline switches to deterministic path-rule mode (`generate.ts:771`). In this mode, `generateL2Nodes()` is never called, so the few-shot section is never built or injected. This means that for mature projects that have completed bootstrap, the self-evolution feedback loop is completely inactive.

3. **No separate L3 few-shot injection**: The `buildFewShotSection()` function is only called in `generateL2Nodes()` (line 245). L3 nodes are generated as part of the same LLM call that generates L2 nodes, so they indirectly benefit from L2 few-shot examples. However, there is no dedicated L3 few-shot injection, which would be more relevant for L3-specific corrections.

## Round 2 — Code Quality & Security Review

### Code Quality Issues

1. **No content length truncation in `buildFewShotSection()`**: At `generate.ts:106-117`, the function concatenates `c.original` and `c.corrected` directly into the prompt without any length limits. If a correction example has very long content (e.g., a full L2 description or L3 content), it could consume a significant portion of the LLM context window. There is no `slice()` or truncation applied.

   ```typescript
   function buildFewShotSection(
     corrections: Array<{ original: string; corrected: string }>
   ): string {
     if (corrections.length === 0) return "";
     const examples = corrections
       .map(
         (c, i) => `Example ${i + 1}:\n  Original: "${c.original}"\n  Corrected: "${c.corrected}"`
       )
       .join("\n");
     return `\n\nPrevious human corrections (use these as quality guidance):\n${examples}`;
   }
   ```

2. **No test coverage for few-shot injection**: The existing test in `generate.test.ts` tests the basic generate flow but does not create any `correction_examples` records before triggering generation. There is no test that verifies:
   - `getRecentCorrections()` returns the correct records
   - `buildFewShotSection()` formats examples correctly
   - The few-shot section is actually included in the LLM prompt
   - The LLM response improves when few-shot examples are present

3. **No test for `buildFewShotSection` edge cases**: Empty corrections array, very long content, special characters in content (quotes, backslashes) — none of these are tested.

4. **Unused `correctionExamplesTable` import in factories**: `factories.ts:5` imports `correctionExamplesTable` but no `CorrectionExampleFactory` is defined. This means tests cannot easily create correction example records to test the few-shot injection flow.

### Security Review

- No security vulnerabilities found in the few-shot injection mechanism.
- The correction content is user-controlled but only used as text in LLM prompts (not executed as code). Prompt injection via corrected content is a theoretical concern but within acceptable bounds for this application.
- The `getRecentCorrections()` function properly filters by `projectId`, preventing cross-project data leakage.

## Round 3 — Integration & Completeness Review

### Integration Points

1. **Review → Correction Examples → Few-shot**: ✅ Works for L2 corrections in bootstrap mode. The flow is: review approval → `correction_examples` table → `getRecentCorrections()` → `buildFewShotSection()` → LLM prompt.
2. **Review → Correction Examples → L3 Few-shot**: ❌ Broken. L3 corrections are stored but never fetched for few-shot injection.
3. **Few-shot → Path-rule mode**: ❌ Not active. In path-rule mode, the generate pipeline bypasses `generateL2Nodes()` entirely.
4. **Distillation → Few-shot**: ⚠️ Indirect. The distillation job in `metabolism.ts` creates guardrails in `prompt_templates`, which are used as system prompts. This is a separate mechanism from few-shot injection. Both mechanisms exist but serve different purposes.

### Test Coverage

- **No tests exist** for the `getRecentCorrections()` function.
- **No tests exist** for the `buildFewShotSection()` function.
- **No tests exist** verifying that few-shot examples are included in the LLM prompt.
- **No tests exist** for the end-to-end flow: create correction → trigger generate → verify correction appears in prompt.
- The existing `generate.test.ts` test does not populate `correction_examples`, so it does not exercise the few-shot path at all.

### Performance Considerations

- `getRecentCorrections()` queries with `ORDER BY createdAt DESC LIMIT 5` but there is no database index on `(projectId, entityType, createdAt)`. With a large number of correction examples, this query could be slow. However, with only 5 rows returned, the practical impact is minimal.
- The few-shot section adds token overhead to each LLM call. With 5 examples and no truncation, this could add 500-2000+ tokens per call depending on content length.

### End-to-End Usability

The feature is partially usable:

- For new projects in bootstrap mode, L2 corrections from review tasks are correctly fetched and injected as few-shot examples into the L2/L3 generation prompt.
- For mature projects in path-rule mode, few-shot injection is completely inactive.
- L3 corrections are stored but never used for few-shot, reducing the effectiveness of the feedback loop.

## Recommendations

1. **Inject L3 corrections as few-shot**: Call `getRecentCorrections(projectId, "l3_node")` and pass the result to the L3 generation path. Since L3 nodes are currently generated inside `generateL2Nodes()`, consider adding a separate L3 generation step that uses L3-specific few-shot examples.

2. **Activate few-shot in path-rule mode**: Even in path-rule mode, few-shot examples could be used for L3 generation or for validating/refining the deterministic assignments. Consider adding a few-shot section to the path-rule branch.

3. **Add content truncation**: Add a max length (e.g., 200 characters) to `c.original` and `c.corrected` in `buildFewShotSection()` to prevent context window overflow:

   ```typescript
   const truncate = (s: string, max = 200) => (s.length > max ? s.slice(0, max) + "..." : s);
   ```

4. **Add test coverage**: Create tests that:
   - Populate `correction_examples` records before triggering generate
   - Verify the few-shot section appears in the LLM prompt (via MSW request inspection)
   - Test `buildFewShotSection` with edge cases (empty, long content, special characters)

5. **Define `CorrectionExampleFactory`**: Add the missing factory in `factories.ts` to enable test authoring.

6. **Add database index**: Add an index on `correction_examples(projectId, entityType, createdAt)` for query performance.

## Overall Verdict

**⚠️ WARN**

The few-shot injection into the generate pipeline is implemented and functional for the L2 correction path in bootstrap mode. The `getRecentCorrections()` and `buildFewShotSection()` functions are well-structured and correctly integrated into the `generateL2Nodes()` flow. However, there are significant gaps: (1) L3 corrections are never injected as few-shot examples, (2) the entire few-shot mechanism is bypassed in path-rule mode (which is the steady-state for mature projects), and (3) there is zero test coverage for this feature. The feature is partially implemented and works for its narrow target scenario (L2 corrections during bootstrap), but the broader self-evolution feedback loop described in ADR-006 is incomplete.
