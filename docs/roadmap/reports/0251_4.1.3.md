# Verification Report: 4.1.3 — Temporal Range Anchors for L3 Nodes (Replaced JSONB)

**Date**: 2026-06-18
**Item**: 4.1.3 — Temporal Range Anchors for L3 nodes (replaced JSONB)
**ADR**: ADR-004 (Git-Isomorphic Graph), ADR-009 (L3 Semantic Deduplication)
**Verdict**: ⚠️ WARN — Schema columns exist and are referenced in query paths, but are never populated during L3 node creation or generation. The old `source_commits` JSONB column and `commit_hash` text column remain as the actual data carriers.

---

## Round 1: Schema & Migration Analysis

### Drizzle TypeScript Schema (`lib/db/src/schema/l3_nodes.ts`)

The `l3NodesTable` defines both temporal anchor columns (lines 35–36):

```ts
introducedInCommit: text("introduced_in_commit"),
verifiedUntilCommit: text("verified_until_commit"),
```

These are nullable `text` columns designed to store commit SHA hashes, replacing the old `sourceCommits` JSONB array approach per ADR-004. The `commitHash` column (line 27) is marked `@deprecated — superseded by sourceCommits[0] (v2)`.

### Migration State (`lib/db/drizzle/0000_short_ezekiel.sql`)

The only migration (`0000_short_ezekiel.sql`, line 85) still contains:

```sql
"source_commits" jsonb,
```

**No subsequent migration exists** to drop `source_commits` or add the new anchor columns. The Drizzle TypeScript schema has evolved past the migration — there is a confirmed schema/migration drift. Only one SQL migration file exists in `lib/db/drizzle/`.

### Drizzle Snapshot (`lib/db/drizzle/meta/0000_snapshot.json`)

The snapshot (lines 522–526) confirms `source_commits` JSONB is still the tracked column. The `introduced_in_commit` and `verified_until_commit` columns are absent from the snapshot.

### OpenAPI Spec (`lib/api-spec/openapi.yaml`)

The `L3Node` component schema (lines 1962–1986) does **not** include `introducedInCommit` or `verifiedUntilCommit` properties. It only lists `commitHash` as the commit reference. The `L3NodeInput` schema (lines 1988–2007) similarly omits them. This means:

- Generated Zod validators will not validate these fields
- Generated React Query hooks will not include them
- API consumers cannot set or read the anchor columns via REST

**Round 1 Findings:**

- ✅ Drizzle TypeScript schema defines both anchor columns correctly
- ❌ Database migration has NOT been updated — `source_commits` JSONB still present, anchor columns not in DB
- ❌ Drizzle snapshot does not include the new anchor columns
- ❌ OpenAPI spec does not expose the new anchor fields
- ❌ `commitHash` (deprecated) remains the only commit reference in the API contract

## Round 2: Population Logic — Are the Anchors Actually Written?

### Generate Route (`artifacts/api-server/src/routes/generate.ts`, lines 1019–1032)

The main L3 node creation path during AI generation:

```ts
const [l3node] = await db
  .insert(l3NodesTable)
  .values({
    l2NodeId: l2node.id,
    title: l3data.title,
    content: l3data.content,
    nodeType: l3data.nodeType ?? "change",
    commitHash: l3data.commitHash || null, // ← deprecated column only
    aiGenerated: true,
    confidence,
    occurrenceCount: 1,
    validityStatus: "pending",
  })
  .returning();
```

**Neither `introducedInCommit` nor `verifiedUntilCommit` is set.** The `l3data.commitHash` value is available in scope and could be mapped to `introducedInCommit`, but this mapping is not implemented.

### L3 Nodes REST Route (`artifacts/api-server/src/routes/l3_nodes.ts`, lines 29–40)

The POST handler for manual L3 creation:

```ts
.values({
  l2NodeId: id,
  title: body.title,
  content: body.content ?? null,
  nodeType: body.nodeType as any,
  commitHash: body.commitHash ?? null,  // ← deprecated column only
  aiGenerated: body.aiGenerated ?? true,
  confidence: body.confidence ?? null,
})
```

No `introducedInCommit` or `verifiedUntilCommit` population.

### VS Code Extension Bridge (`artifacts/api-server/src/lib/extensions-service.ts`, lines 34–46)

The `createL3Decision` function:

```ts
.values({
  l2NodeId,
  title: payload.l3Node.title,
  content: payload.l3Node.content ?? null,
  nodeType: (payload.l3Node.nodeType ?? "decision") as any,
  commitHash: payload.l3Node.commitHash ?? null,  // ← deprecated column only
  aiGenerated: payload.l3Node.aiGenerated ?? false,
  confidence: payload.l3Node.confidence ?? null,
  embedding: embRaw,
})
```

Same pattern — temporal anchors not populated.

### Query/Read Path (`artifacts/api-server/src/lib/intent-router.ts`, lines 492–496)

The hash-based lookup **does** use `introducedInCommit`:

```ts
const l3Nodes = await db
  .select()
  .from(l3NodesTable)
  .where(like(l3NodesTable.introducedInCommit, `${searchQuery}%`))
  .limit(limit);
```

This is the **only place** in the codebase that reads `introducedInCommit`. Since the column is never populated, this query will always return empty results for hash lookups — a silent failure affecting item 3.3.1 (O(1) Fast-Path Filters).

### Export Route (`artifacts/api-server/src/routes/export.ts`, line 169)

The Markdown export reads `introducedInCommit`:

```ts
res.write(`- **Introduced in**: \`${l3.introducedInCommit ?? "Unknown"}\`\n\n`);
```

This will always display "Unknown" since the column is never populated.

**Round 2 Findings:**

- ❌ `introducedInCommit` is **never written** in any L3 insertion path (generate, REST API, VS Code bridge)
- ❌ `verifiedUntilCommit` is **never written** anywhere in the codebase
- ✅ `introducedInCommit` is **read** by intent-router hash lookup and export — but will always be null
- ❌ The deprecated `commitHash` column is still the only one being populated with commit SHAs

## Round 3: Cross-Check with ADRs, Tests, and Edge Cases

### ADR-004 Compliance Matrix

| Requirement                                     | Status                           |
| ----------------------------------------------- | -------------------------------- |
| `introduced_in_commit` column exists in schema  | ✅ Yes (TypeScript only)         |
| `verified_until_commit` column exists in schema | ✅ Yes (TypeScript only)         |
| Columns populated during L3 creation            | ❌ No                            |
| `source_commits` JSONB removed from DB          | ❌ No (still in migration)       |
| Anchor columns exposed in OpenAPI               | ❌ No                            |
| Hash lookup uses `introduced_in_commit`         | ✅ Yes (but data is always null) |

### ADR-009 Compliance

ADR-009 (L3 Semantic Deduplication) references the temporal anchors as part of the L3 dedup lifecycle. The `occurrenceCount` column (4.1.2) is populated correctly, but the temporal anchors that should track _when_ a deduplicated node was introduced are not set.

### Test Coverage

The test factory `L3NodeFactory.build()` (`artifacts/api-server/test/support/factories.ts`, lines 55–61) does not set `introducedInCommit` or `verifiedUntilCommit`:

```ts
build: (l2NodeId: number, overrides?: Partial<InsertL3Node>): InsertL3Node => ({
  l2NodeId,
  title: faker.lorem.words(3),
  content: faker.lorem.paragraph(),
  nodeType: "change",
  ...overrides,
}),
```

No tests were found that verify temporal anchor population.

### Edge Cases

1. **Hash lookup always empty**: The intent-router's O(1) fast-path for commit hash queries (item 3.3.1) searches `introducedInCommit` — this feature is non-functional.
2. **Export always shows "Unknown"**: The Markdown export will never show the actual introducing commit.
3. **verifiedUntilCommit never updated**: There is no logic to update this column when a commit invalidates an L3 node (e.g., when code is removed or changed).
4. **Schema/migration drift**: The Drizzle TypeScript schema and the actual database schema are out of sync. A new migration must be created to add the columns to the actual database.

## Recommendation

**WARN** — The Temporal Range Anchors are architecturally designed and present in the Drizzle TypeScript schema, but the implementation is not yet functional. The columns are never populated, never exposed in the API contract, and the database migration has not been updated. To complete this item:

1. Create a Drizzle migration to add `introduced_in_commit` and `verified_until_commit` columns to the actual database
2. Update all L3 insertion points to set `introducedInCommit = commitHash` at creation time
3. Add logic to update `verifiedUntilCommit` when L3 nodes are invalidated
4. Expose both fields in the OpenAPI `L3Node` and `L3NodeInput` schemas
5. Add test factories and integration tests that verify anchor population
