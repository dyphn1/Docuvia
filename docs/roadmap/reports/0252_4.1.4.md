✅ Loaded from DB config with correct fallback defaults. Respects per-project configuration.

**CRITICAL GAP — `sourceCommits` column mismatch:**

The `l3_nodes` Drizzle schema (`l3_nodes.ts:18–39`) defines these columns:
- `introducedInCommit: text("introduced_in_commit")` (line 35)
- `verifiedUntilCommit: text("verified_until_commit")` (line 36)

But does **NOT** define `sourceCommits`. Meanwhile:
- The migration SQL (`0000_short_ezekiel.sql:85`) still has `"source_commits" jsonb`
- The Drizzle snapshot (`meta/0000_snapshot.json:522–527`) still has `source_commits` as a jsonb column
- The `condenseL3Node()` function (line 126) reads `node.sourceCommits` and casts it to `string[]`

Because the Drizzle schema omits `sourceCommits`, the `db.select().from(l3NodesTable)` query at line 957–960 will **never return** a `sourceCommits` property. The Drizzle ORM only maps columns defined in the schema. When `condenseL3Node(bestL3Match)` is called at line 999, `bestL3Match.sourceCommits` will be `undefined`, and `condenseL3Node` returns `null` at line 127 (`if (!commits.length) return null`).

**The condensation function is non-functional in the current codebase.**

## Round 2 — Implementation Analysis

**Condensation trigger logic** (`generate.ts:997–1016`):
```typescript
if (newOccurrenceCount >= condensationThreshold) {
  const condensed = await condenseL3Node(bestL3Match as any, model);
  if (condensed) {
    await db.update(l3NodesTable).set({ content: condensed })...;
  }
  if (condensationReviewRequired) {
    await db.insert(reviewTasksTable).values({ ... });
  }
}
```
✅ Trigger condition is correct: `>=` comparison against the configurable threshold.
✅ Content update path is correct (only updates if condensation returns non-null).
✅ Review task creation is gated by `condensationReviewRequired` flag.

**`condenseL3Node()` function** (`generate.ts:122–178`):
- Accepts `node.sourceCommits` as an array of commit hashes (line 123, 126)
- Early-returns `null` if empty (line 127)
- Batches commits in groups of 20 (line 131, 134) — progressives through all source commits
- For each batch: fetches commit data from `commitsTable` (lines 137–140), builds summary string (lines 144–146), calls OpenAI API (lines 149–163)
- Chains synthesis across batches: each batch receives `synthesizedContent` from prior batch in the `user` prompt (line 160)
- 500ms sleep between batches for rate limit protection (line 166)
- Returns final `synthesizedContent` or `null` (line 173)

**Internal logic quality (assuming data were present):**
✅ Progressive batching (20 commits per batch) — prevents context overflow
✅ Chained synthesis — each batch sees output of previous batch, building coherent content
✅ Rate limiting — 500ms delay between API calls
✅ Error handling — inner catch + re-throw (line 167–170), outer catch logs and returns null (line 174–177)
⚠️ The `throw e` on line 169 means a single failed batch aborts the entire condensation. A partial-failure approach (log warning, continue with next batch) would be more resilient.

**Type safety issue:**
❌ The function signature accepts `sourceCommits: unknown` and manually checks `Array.isArray()` — this is a workaround for the missing column. If the column were properly defined in the Drizzle schema, this manual type wouldn't be needed.

## Round 3 — Integration, Edge Cases & Tests

**Test coverage:**
- ❌ No integration test verifies condensation fires at `occurrenceCount >= 30`
- ❌ No integration test verifies `occurrenceCount` exactly at threshold (30) triggers condensation
- ❌ No integration test verifies `occurrenceCount` at threshold - 1 (29) does NOT trigger condensation
- ❌ No test for `condensationReviewRequired = true` creating a review task post-condensation
- ❌ No test for `condensationReviewRequired = false` skipping review task creation
- ❌ No test for condensation returning `null` (content unchanged)
- ❌ No test for the batching logic within `condenseL3Node`
- ❌ No test for rate limiting / error handling in condensation

**Edge cases not handled:**

1. **Repeated condensation trigger (CRITICAL):** Once `occurrenceCount` reaches 30 and condensation fires, the next increment (31) will trigger condensation *again* because the code doesn't track that condensation already ran. Every subsequent occurrence re-triggers the full AI synthesis, making cost O(n) per occurrence past the threshold. The ADR doesn't explicitly call this out, but a production system should either:
   - Reset `occurrenceCount` after condensation
   - Track a `lastCondensedAt` timestamp and skip re-triggering
   - Only trigger on exact threshold match (`===` instead of `>=`)

2. **Concurrent condensation race:** Two generate requests that both increment to the threshold simultaneously could both trigger `condenseL3Node` concurrently, resulting in redundant API calls and potential write conflicts on the `content` update.

3. **No source commits fallback:** The ADR says condensation uses `sourceCommits` as input. But the schema migration to temporal anchors (`introducedInCommit`/`verifiedUntilCommit`) broke this linkage. If the team intended commits linked via `commit_l2_links` or `commitsTable` to serve as the source, that join logic is missing.

**Schema drift between migration and Drizzle schema:**
| Column | Migration SQL | Drizzle Schema | Status |
|--------|--------------|----------------|--------|
| `source_commits` jsonb | ✅ Present (line 85) | ❌ Missing from `l3_nodes.ts` | **Drift** |
| `introduced_in_commit` text | ❌ Missing from SQL | ✅ Present (line 35) | **Drift** |
| `verified_until_commit` text | ❌ Missing from SQL | ✅ Present (line 36) | **Drift** |

The migration SQL and Drizzle schema for `l3_nodes` are inconsistent. The migration has `source_commits` but not the temporal anchors; the Drizzle schema has the temporal anchors but not `source_commits`. This suggests an incomplete migration — someone updated the Drizzle schema to replace `source_commits` with temporal anchors but forgot to add a new migration SQL file to apply the change to the database.

## Gaps & Recommendations

1. **CRITICAL: `sourceCommits` column missing from Drizzle schema** — The condensation function reads `node.sourceCommits` but the `l3_nodes.ts` Drizzle schema does not define this column, so `db.select()` never returns it. The condensation path is **dead code** at runtime. Fix options:
   - **Option A:** Add `sourceCommits: jsonb("source_commits")` back to the Drizzle schema to match the migration SQL. This is the simplest fix and restores the ADR-009 design.
   - **Option B:** Rewrite `condenseL3Node` to derive commit hashes from the `commits` table (joining via `commit_l2_links` on the L2 parent, or using `introducedInCommit` as a starting point). This aligns with the temporal anchor migration but requires more complex query logic.
   - **Option C:** Add a new migration that adds `source_commits` to the DB AND adds it to the Drizzle schema, then backfills from existing data.

2. **HIGH: Repeated condensation trigger** — No guard against re-triggering. Once `occurrenceCount` hits 30, every subsequent occurrence (31, 32, 33...) will re-run the full AI condensation, burning tokens unnecessarily. Add one of:
   - Reset `occurrenceCount` to 0 after condensation
   - Add a `lastCondensedAt` timestamp and skip if already condensed
   - Trigger on `===` instead of `>=` (simplest but means threshold+1 through threshold+19 are "wasted")

3. **HIGH: Schema drift between migration SQL and Drizzle schema** — The migration has `source_commits` but not temporal anchors; Drizzle schema has temporal anchors but not `source_commits`. A proper migration file should reconcile these. Recommend adding a Drizzle migration that:
   - Adds `introduced_in_commit text` and `verified_until_commit text` columns to the DB
   - Optionally drops `source_commits` if the temporal anchor approach is intentional
   - Updates the Drizzle snapshot accordingly

4. **MEDIUM: Partial batch failure handling** — The `throw e` on line 169 aborts the entire condensation if one batch fails. Consider allowing partial synthesis (skip failed batch, continue with next) to maximize value from successful batches.

5. **MEDIUM: No test coverage** — Need at least:
   - Test: `occurrenceCount` reaches condensation threshold → `condenseL3Node` is called
   - Test: `occurrenceCount` below threshold → condensation not triggered
   - Test: `condensationReviewRequired = true` → review task created
   - Test: `condensationReviewRequired = false` → no review task
   - Test: condensation returns null → content not updated
   - Test: condensation returns content → content updated in DB
