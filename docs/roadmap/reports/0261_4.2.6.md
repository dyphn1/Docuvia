| `lib/db/drizzle/meta/0000_snapshot.json` | Drizzle snapshot captures the table structure including all columns, indexes, and foreign keys |

### Round 1 Finding

**Schema is properly defined.** The junction table exists with correct structure: serial PK, two FK columns with cascade deletes, a unique constraint on `(commit_id, l2_node_id)`, and btree indexes on both FK columns for efficient lookups in both directions. The `commits.l2NodeId` column is marked `@deprecated` in the source code and is nullable (not NOT NULL), consistent with a deprecation path.

**⚠️ Schema Drift Detected:** The SQL migration (`0000_short_ezekiel.sql` line 43) and the Drizzle snapshot (`0000_snapshot.json` line 180) both include a `diff_paths jsonb` column on `commit_l2_links`, but the Drizzle ORM schema (`commit_l2_links.ts`) does NOT define this column. This means:
- The column exists in the actual database but is invisible to the ORM — Drizzle will never read or write it.
- No code in the codebase references `diff_paths` anywhere (confirmed via grep).
- This is either a vestigial column from a design iteration or planned-for-future-use. It is harmless but represents schema drift between the ORM definition and the actual DB.

**Round 1 Verdict: PASS** — The junction table is correctly created and the deprecated `commits.l2NodeId` column is properly nullable with a deprecation annotation.

## Round 2: Usage Verification (Is the Junction Table Actually Used?)

### Evidence

| File | Lines | Finding |
|------|-------|---------|
| `artifacts/api-server/src/routes/generate.ts` | 846-859 | **Path-rule mode:** After matching a commit to an L2 node via glob patterns, writes to BOTH `commitsTable.update({ l2NodeId })` (deprecated) AND `commitL2LinksTable.insert()` with `.onConflictDoNothing()` |
| `artifacts/api-server/src/routes/generate.ts` | 1063-1072 | **L3 generation path:** When creating L3 nodes, also writes to both `commitsTable.update({ l2NodeId })` and `commitL2LinksTable.insert()` (comment: "Also insert into commit_l2_links junction table (v2)") |
| `artifacts/api-server/src/routes/generate.ts` | 451-455 | **L3 node scoring:** Reads from `commitL2LinksTable` to get `commitLinkedNodeIds` for scoring L3 node placement — uses the junction table as the source of truth for commit→L2 relationships |
| `artifacts/api-server/src/routes/l2_nodes.ts` | 87-90 | **Module rejection:** When rejecting L2 modules, reassigns commits in `commitL2LinksTable` (not the deprecated `commits.l2NodeId`) to the sys-uncategorized node |

### Round 2 Finding

**The junction table is actively used in 4 places across 2 route files:**

1. **Writes (2 sites):** Both the path-rule assignment path (line 852-858) and the L3 generation path (line 1069-1072) insert into `commitL2LinksTable`. Both use `.onConflictDoNothing()` (path-rule) or `.catch(() => {})` (L3 path) for idempotency.

2. **Reads (1 site):** The L3 scoring logic (line 453) queries `commitL2LinksTable` to determine which L2 nodes a commit is linked to, using this as a scoring signal (W1 weight).

3. **Updates (1 site):** The module rejection logic (line 88-90) updates `commitL2LinksTable` directly to reassign commits from rejected modules to the system uncategorized node.

**⚠️ Dual-write pattern:** Both write sites also update the deprecated `commits.l2NodeId` column. This is a backward-compatible dual-write strategy — the old column is kept in sync during the migration period. The `l2_nodes.ts` rejection logic correctly uses only the junction table (not the deprecated column) for the update, which is the right direction.

**⚠️ Missing `.onConflictDoNothing()` on L3 path:** The L3 generation path (line 1069-1072) uses `.catch(() => {})` instead of `.onConflictDoNothing()`. While functionally similar (both silently handle duplicate inserts), the `.onConflictDoNothing()` pattern is more explicit and consistent with the path-rule path. This is a minor inconsistency, not a bug.

**Round 2 Verdict: PASS** — The junction table is the primary mechanism for commit↔L2 linking. It is read, written, and updated in production code paths.

## Round 3: Completeness & ADR-010 Compliance

### ADR-010 Requirements for commit_l2_links

From `docs/design/09-architectural-decisions.md` (ADR-010):

| Requirement | Status | Evidence |
|-------------|--------|----------|
| Junction table must be created | ✅ Done | `commit_l2_links.ts` + SQL migration + snapshot |
| `commits.l2NodeId` is deprecated | ✅ Done | `@deprecated` comment in `commits.ts` line 16; column is nullable |
| Supports many-to-many (commit ↔ L2) | ✅ Done | Composite unique constraint on `(commit_id, l2_node_id)`; no restriction preventing multiple L2 nodes per commit |
| Used for deterministic commit-to-module assignment | ✅ Done | Path-rule mode in `generate.ts` lines 846-859 |
| Historical rows flagged with `reindexRequired: true` on bootstrap confirmation | ❌ Not implemented | The `reindexRequired` column exists on `l2_nodes` table, but `generate.ts` never sets it on `commit_l2_links` rows when bootstrap is confirmed. No code references `reindexRequired` in the context of `commit_l2_links`. |
| Retroactively corrected on next generate run | ❌ Not implemented | No logic exists to re-process historical `commit_l2_links` rows after path patterns are saved |

### Round 3 Finding

**The junction table itself is fully implemented and operational.** However, ADR-010 specifies a consequence that is NOT implemented: when the bootstrap L2 module map is confirmed and path patterns are saved, historical `commit_l2_links` rows should be flagged for reindexing and retroactively corrected on the next generate run. This is a known gap — the previous verification report for 4.2.1 (report 0256_4.2.1.md, Finding 11) already identified this.

**This is a partial gap in ADR-010 compliance, but it is specifically about the `reindexRequired` flag logic, which is tracked under item 4.2.2 (AI self-correction across batches).** The 4.2.6 item specifically covers the junction table creation and deprecation of `commits.l2NodeId`, both of which are complete.

**Round 3 Verdict: PASS** — The junction table is implemented and the deprecated column is properly marked. The `reindexRequired` flag logic is out of scope for this item (tracked under 4.2.2).

### Overall: ✅ PASS

The `commit_l2_links` junction table is fully implemented and is the primary mechanism for commit↔L2 node relationships. The deprecated `commits.l2NodeId` column is properly marked and kept in sync via dual-write. One minor schema drift issue exists (`diff_paths` column in DB but not in ORM) but is harmless.

### Recommendations

1. **Add `diff_paths` to the Drizzle schema** if it's intended for future use, or **remove it from the migration/SQL** if it's vestigial. Having a column that the ORM can't see is a maintenance hazard.
2. **Standardize error handling** — use `.onConflictDoNothing()` consistently instead of `.catch(() => {})` for the L3 path insert (line 1069-1072).
3. **Plan removal of dual-write** — once all readers have migrated to the junction table, stop writing to `commits.l2NodeId` and eventually drop the column (tracked as "v3" in the deprecation comment).
