### Enum Constraint

ADR-011 specifies enum: `pending | valid | orphaned`.

- ⚠️ **No `pgEnum` constraint** — The column is plain `text`, not a PostgreSQL enum. Values are enforced at the application level.
- ⚠️ **`"orphaned"` never written** — The `github_webhooks.ts` handler for `closed` (not merged) PR action only updates `pullRequestsTable.state = "closed"` but does NOT set associated L3 nodes to `"orphaned"`. The metabolism path also only promotes to `"valid"`.
- This means the `"orphaned"` enum value is defined in the spec but never populated in practice.

**Round 3 Findings:**
- ✅ Column is correctly used for its primary purpose: default `"pending"`, promoted to `"valid"` on merge.
- ✅ Write paths are semantically correct (generate creates pending, merge webhook promotes to valid).
- ⚠️ No DB-level enum constraint — values are application-enforced (acceptable for Drizzle text columns, but worth noting).
- ⚠️ `"orphaned"` value is never written — the orphaning logic (PR closed without merge) is not implemented. This is a gap in Phase 2 of ADR-011, but it does not affect the schema column itself.
- ❌ The `'active'` bug in `intent-router.ts` is a known issue (tracked in 4.3.3, 4.3.4, 4.3.5) but is a filter-logic bug, not a schema-column bug.

**Round 3 Verdict: PASS** — The schema column exists, is correctly defined, and is used for its intended purpose. The application-level bugs (orphaned logic, `'active'` filter) are tracked under other items (4.3.3, 4.3.4, 4.3.5) and do not affect the schema column verification.

## Gaps & Notes

1. **No `pgEnum` on the column.** The ADR says enum `pending | valid | orphaned` but the implementation uses plain `text`. This is a common pattern in Drizzle (application-enforced enums) and is acceptable, but a `pgEnum` would provide DB-level validation. Low priority.

2. **The `'active'` bug is out of scope for this item.** The filter-logic bug in `intent-router.ts:500,535` is verified under items 4.3.3, 4.3.4, and 4.3.5. This item only verifies the schema column existence.

3. **The `"orphaned"` transition is out of scope for this item.** The orphaning logic (setting status to `"orphaned"` when a PR is closed without merging) is a Phase 2 behavior tracked under item 4.3.2. This item only verifies the column exists in the schema.

## Final Verdict: PASS

The `validityStatus` column is correctly defined on both `l3_nodes` and `commits` tables, matching ADR-011's schema requirements. The migration SQL is in sync with the Drizzle schema. The column is actively used in the generate pipeline and merge-gate flow. Application-level bugs in filter logic and the missing `"orphaned"` transition are tracked under separate items.
