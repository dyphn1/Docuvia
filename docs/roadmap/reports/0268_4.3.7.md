# Verification Report: Item 4.3.7 — Schema: branchName column on commits

**Item ID:** 4.3.7
**Description:** The `commits` table must have a `branchName` column (text, nullable) to track which branch a commit belongs to
**Date:** 2026-06-20
**Verdict:** WARN

## Design Spec References

- ADR-011 Two-Phase Knowledge Validity (from `docs/design/09-architectural-decisions.md`, lines 270-299):
  - Consequence: "⚠️ `commits` table requires `branchName text` column"
- Item 4.3.8: Branch merge status tracking (depends on branch identification)

## Round 2 — Data Flow & Write Path Coverage

**Does any code path actually populate the `branchName` column when inserting commits?**

### Git Ingestion Route (`ingest.ts:35-99`)

The git ingest route calls `client.getCommits()` which returns `GitCommitData[]`. The `GitCommitData` interface (`git-client.ts:12-19`) does include `branchName?: string`.

However, the ingest route passes items to `processIngestion()` as `GitCommitItem[]`.

### Ingestion Pipeline (`ingestion-pipeline.ts:23-29`)

```typescript
export interface GitCommitItem {
  sha: string;
  message: string;
  author: string;
  date?: string;
  diff?: string;
}
```

- ❌ **`branchName` is NOT included in `GitCommitItem` interface**
- The field is stripped when mapping `GitCommitData` → `GitCommitItem` in `ingest.ts:62-65`

### processIngestion Write (`ingestion-pipeline.ts:90-97`)

```typescript
await tx.insert(commitsTable).values({
  projectId,
  hash: c.sha,
  message: c.message.slice(0, 4000),
  author: c.author ?? "Unknown",
  valid,
  vcsType: "git",
});
```

- ❌ **`branchName` is NOT written** — the insert object omits it entirely

### GitHub Webhook PR Ingestion (`github_webhooks.ts:58-64`)

```typescript
await db.insert(commitsTable).values({
  projectId,
  hash: c.sha,

  valid: true,

```

- ❌ **`branchName` is NOT written** — webhook ingestion also omits it

### REST API POST /commits (`projects.ts:204-214`)

```typescript

  projectId: id,

  message: body.message,
  author: body.author,
  valid: body.valid ?? true,
```

- ❌ **`branchName` is NOT accepted or written** — `CreateCommitBody` schema does not include `branchName`

### Test Factory (`factories.ts:75-82`)

```typescript

  build: (projectId: number, overrides?: Partial<InsertCommit>): InsertCommit => ({
```

- ❌ **`branchName` is NOT set** in the default factory (though it can be passed via overrides)

**Round 2 Findings:** The column exists in the schema but is NEVER populated by any write path:

1. The `GitCommitItem` interface drops `branchName` before it reaches the pipeline
2. The `processIngestion` function does not include `branchName` in the insert
3. The GitHub webhook handler does not include `branchName`
4. The REST API `CreateCommitBody` does not accept `branchName`
5. The test factory does not set `branchName`

The `getCurrentBranchName()` method exists on `LocalGitClient` but is never called during ingestion.

**Round 2 Verdict: FAIL** — The column exists but no code path writes to it.

## Round 3 — Semantic Impact & Gap Analysis

**What is the impact of the missing `branchName` data?**

### Downstream Consumers

1. **Branch merge status tracking (Item 4.3.8):** The merge gate in `github_webhooks.ts:255-292` updates `l3_nodes.validityStatus` based on PR commit hashes, but does NOT filter by branch. The `branchName` on commits would enable tracking which branch a commit belongs to for merge detection. Without it, the system relies solely on PR metadata for merge status.

2. **Orphan detection:** Without `branchName`, the system cannot detect commits that were on a branch that was closed without merging (the "orphaned" status in ADR-011's enum).

3. **Diff projection (`getProjectedCommits`):** The `git-client.ts:97-115` method uses `merge-base HEAD origin/main` to scope commits, which implicitly handles branching. But it does not store the branch name for later reference.

### Is the Column Used in Any Query?

- ❌ No `SELECT` queries reference `commits.branchName`
- ❌ No `WHERE` clauses filter on `branchName`
- ❌ No API responses expose `branchName` (though it would be returned via the generic `commitsTable` select)

### Could the Column Be Removed?

The column is harmless as-is (nullable, no constraints). However, it represents an incomplete implementation:

- The schema was added per ADR-011's requirement
- The data flow was never wired to populate it
- Downstream features (4.3.8) may need it

**Round 3 Findings:**

- The missing data has **low immediate impact** because the current merge-gate logic uses PR metadata rather than commit `branchName`
- The gap **blocks proper orphan detection** (PR closed without merge → commits orphaned) since there's no branch-level tracking
- The `getCurrentBranchName()` method exists but is unused — the plumbing is half-built
- Fixing this requires: (a) adding `branchName` to `GitCommitItem`, (b) populating it in the ingest pipeline, (c) optionally adding it to `CreateCommitBody`

**Round 3 Verdict: WARN** — Schema is correct but data flow is broken. The feature is partially implemented (column exists, source data available, but the write path drops it).

## Gaps & Notes

1. **Data flow break at `GitCommitItem`.** The `GitCommitData` interface has `branchName`, but when `ingest.ts:62-65` maps to `GitCommitItem`, the field is dropped. This is the root cause.

2. **Fix is straightforward:** Add `branchName?: string` to `GitCommitItem`, pass it through in `ingest.ts:62`, and include it in the `tx.insert(commitsTable).values({...})` call in `ingestion-pipeline.ts:90-97`.

3. **The `getCurrentBranchName()` method is unused dead code.** It was presumably added to support this feature but the call site was never implemented. It could be called during git ingest to populate `branchName` for all commits in a batch (they all share the same branch in a clone).

4. **The REST API `CreateCommitBody` also needs updating** if manual commit creation should support branch assignment.

5. **Impact on 4.3.8:** Item 4.3.8 (Branch merge status tracking) may require `branchName` to implement proper orphan detection when a PR is closed without merging. This is a dependency to track.

## Final Verdict: WARN

The `branchName` column is correctly defined in the schema and migration SQL, and the source data is available via `GitCommitData` / `getCurrentBranchName()`. However, the data flow has a break: the `GitCommitItem` interface drops the field, and no write path (ingest pipeline, webhook, REST API) populates the column. The column is effectively unused. The fix is straightforward (wire the field through the pipeline) but until fixed, the feature is incomplete. The immediate functional impact is low because the current merge-gate uses PR metadata rather than commit-level branch tracking.
