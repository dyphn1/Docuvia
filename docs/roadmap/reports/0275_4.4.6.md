## Round 1 — Schema Presence & Type Verification

### Drizzle ORM Schema (`lib/db/src/schema/documents.ts`)

The `documentsTable` defines both columns at lines 24–25:

```typescript
contentHash: text("content_hash"),
affiliatedAt: timestamp("affiliated_at"),
```

Both columns are **nullable** (no `.notNull()`), which is correct:
- `contentHash` should be nullable because it's computed at upload time and may not exist for pre-existing rows
- `affiliatedAt` should be nullable because misc pool documents have no affiliation until explicitly associated

An index is defined on `contentHash` (line 30):
```typescript
contentHashIdx: index("doc_content_hash_idx").on(table.contentHash),
```

This supports efficient deduplication lookups via `WHERE content_hash = $1`.

## Round 2 — Code Usage & Semantic Correctness

### contentHash Usage

**Upload path** (`documents.ts:126`): SHA-256 hash is computed from the file stream at upload time:
```typescript
const contentHash = await computeHashFromStream(filePath);
```
The hash is stored in the `contentHash` column on insert (line 133).

**Deduplication path** (`ingestion-pipeline.ts:156`): The pipeline checks for existing documents by `contentHash` before inserting:
```typescript
const hash = doc.contentHash ?? crypto.createHash("sha256").update(doc.content).digest("hex");
const [existing] = await db.select({ id: documentsTable.id })
  .from(documentsTable)
  .where(and(eq(documentsTable.projectId, projectId), eq(documentsTable.contentHash, hash)));
```
If a match is found, the document is skipped (dedup). If no `contentHash` is provided, it falls back to computing one from the content.

**Build artifact path** (`ingest.ts:370`): Also computes `contentHash` via `computeHashFromStream` for build artifacts.

### affiliatedAt Usage

**Affiliate endpoint** (`documents.ts:72`): Set to `new Date()` when a document is associated with a project:
```typescript
.set({ projectId, affiliatedAt: new Date(), status: "affiliated" })
```

**Serialization** (`documents.ts:34,85`): Properly serialized to ISO-8601 string in API responses:
```typescript
affiliatedAt: d.affiliatedAt?.toISOString() ?? null
```

### Index Coverage

The `doc_content_hash_idx` index on `contentHash` supports:
1. Deduplication lookups in the ingestion pipeline
2. Fast queries by hash for the misc pool

No index is needed on `affiliatedAt` since it's only used for display/serialization, not for filtering or joining.

### Migration Completeness

There is only one migration (`0000_short_ezekiel.sql`) and it includes both columns. No subsequent migrations have modified these columns. The Drizzle snapshot is in sync with the migration SQL.

### Schema Evolution Check

The `documents` table also has a `status` column (text, default `'unaffiliated'`) that works alongside `affiliatedAt`:
- `status: 'unaffiliated'` + `affiliatedAt: null` → misc pool document
- `status: 'affiliated'` + `affiliatedAt: <timestamp>` → associated document

This dual-track approach is consistent and provides both a quick enum filter and a precise timestamp.
