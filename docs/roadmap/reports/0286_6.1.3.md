## Round 1 — Architecture & Design Review

### What the Design Spec Says

The API server should be decomposed into 21 route modules, each handling a distinct domain of the API. The routes are registered centrally in `routes/index.ts` and mounted under `/api` in `app.ts`. Each route module should export an Express Router with properly typed handlers.

### What the Implementation Provides

**All 21 route modules are present, valid, and mounted:**

1. **`routes/index.ts`** imports all 21 routers and mounts them via `router.use()`. The imports match the file system exactly — no missing modules, no typos, no orphaned imports.

2. **Every route file exports a valid Router.** All 21 files use `Router()` from Express and export it as the default export (except `metabolism.ts` which uses a named export `metabolismRouter`, correctly handled in the index).

3. **Every route file contains at least one handler.** No stub files, no empty routers. The smallest module (`health.ts`) has 1 handler; the largest (`generate.ts`) has 10+.

4. **Route mounting is clean.** `app.ts` mounts the main router at `/api`, plus two additional routers:
   - `github_webhooks` at `/api/webhooks/github` (with raw body middleware for HMAC validation)
   - `llmProxyRouter` at `/proxy/v1` (OpenAI-compatible proxy)

5. **The 21 modules cover all domains** listed in AGENTS.md's API Server Routes section:
   - projects, commits, l1_tags, l2_nodes, l3_nodes, review_tasks, dashboard, ingest, generate, export, search, mcp, extensions_vscode, integrations, templates, github_webhooks, pull_requests, notifications, subscriptions, llm_config, health
   - Note: `commits` handlers are embedded within `projects.ts` (project-scoped commits), and `sync` and `documents` are additional modules not explicitly listed in AGENTS.md's route list but present in the codebase.

**Round 1 Verdict: PASS** — All 21 route modules exist, export valid routers, contain handlers, and are properly mounted. The architecture matches the design spec.

## Round 2 — Code Quality & Security Review

**Positive findings:**

1. **Consistent Router pattern.** All 21 modules follow the same pattern: import `Router`, create instance, define handlers, export default. This consistency makes the codebase maintainable. ✅

2. **Zod validation is widely used.** Most routes import Zod schemas from `@workspace/api-zod` for request validation:
   - `projects.ts`: Uses `CreateProjectBody`, `UpdateProjectParams`, `UpdateProjectBody`, `DeleteProjectParams`, `GetProjectParams`, etc.
   - `l1_tags.ts`: Uses `CreateL1TagBody`, `UpdateL1TagParams`, `UpdateL1TagBody`, `DeleteL1TagParams`
   - `l2_nodes.ts`: Uses `CreateL2NodeBody`, `UpdateL2NodeParams`, `UpdateL2NodeBody`, `DeleteL2NodeParams`, `ConfirmBootstrapBody`
   - `l3_nodes.ts`: Uses `ListL3NodesParams`, `CreateL3NodeParams`, `CreateL3NodeBody`, `UpdateL3NodeParams`, `UpdateL3NodeBody`, `DeleteL3NodeParams`
   - `review_tasks.ts`: Uses `ResolveReviewTaskParams`, `ResolveReviewTaskBody`
   - `ingest.ts`: Uses `IngestSvnBody`, `IngestDocumentBody`
   - `subscriptions.ts`: Uses `CreateSubscriptionBody`, `DeleteSubscriptionParams`, `ListProjectSubscriptionsParams`
   - `notifications.ts`: Uses `ListProjectNotificationsParams`, `ListProjectNotificationsQueryParams`, `MarkNotificationReadParams`, `MarkAllNotificationsReadBody`
   - `health.ts`: Uses `HealthCheckResponse` ✅

3. **Error handling is present.** All async handlers use try/catch with proper error responses and logging via `logger.error()`. ✅

4. **Security measures in place:**
   - `github_webhooks.ts`: HMAC-SHA256 signature validation with timing-safe comparison
   - `documents.ts`: Magic byte validation (PDF/DOCX/PPTX), file count quota for misc pool
   - `mcp.ts`: Bearer token auth middleware on all `/mcp/*` routes
   - `metabolism.ts`: Admin secret token auth with dev fallback only in development mode
   - `export.ts`: Project ownership check middleware (IDOR prevention) ✅

5. **Date serialization is consistent.** All routes convert `Date` objects to ISO strings before JSON serialization (`.toISOString()` pattern). ✅

**Issues identified:**

1. **🟡 Some routes define inline Zod schemas instead of using generated ones.** The following routes define their own `z.object({...})` schemas:
   - `search.ts`: `SearchSchema`, `FeedbackSchema`
   - `l2_nodes.ts`: `NodeLinkInputSchema`
   - `templates.ts`: `TemplateUpdateSchema`
   - `documents.ts`: `AffiliateBodySchema`
   - `integrations.ts`: `IntegrationInputSchema`, `IntegrationUpdateSchema`
   - `llm_config.ts`: `LlmConfigInputSchema`
   - `extensions_vscode.ts`: `VscodeQuerySchema`, `VscodeCreateDecisionSchema`
   - `mcp.ts`: `mcpQueryBodySchema`
   - `generate.ts`: `GenerateInputSchema`, `SieveExtractionInputSchema`
   - `ingest.ts`: `GitIngestSchema`
   
   This is a code quality concern (also noted in 6.1.2 report) but does not prevent the routes from functioning. The routes are still implemented and operational.

2. **🟡 `metabolism.ts` uses named export instead of default export.** While correctly handled in `index.ts`, this breaks the pattern used by all other 20 modules. Minor consistency issue.

3. **🟢 `generate.ts` is the largest route file at 1210 lines.** This is a code organization concern — the generate pipeline could potentially be split into sub-routes. However, it is functional and complete.

**Round 2 Verdict: PASS** — All 21 modules are implemented with proper error handling, security measures, and consistent patterns. The inline Zod schema issue is a code quality concern (already tracked in 6.1.2) but does not affect the completeness of route implementation.

## Gaps & Recommendations

1. **🟡 Standardize Zod schema sourcing.** 10 route files define inline Zod schemas for types that likely exist in the OpenAPI spec. These should be migrated to use generated schemas from `@workspace/api-zod` (tracked in 6.1.2 report).

2. **🟡 Fix `metabolism.ts` export pattern.** Change from named export (`export { metabolismRouter }`) to default export for consistency with all other 20 modules.

3. **🟢 Consider splitting `generate.ts`.** At 1210 lines, the generate route file is the largest in the codebase. Consider extracting sub-routes (e.g., `generate-l1.ts`, `generate-l2.ts`, `generate-l3.ts`) for better maintainability.

4. **🟢 Add `sync` and `documents` to AGENTS.md route list.** The AGENTS.md documentation lists 21 route directories but doesn't include `sync` and `documents`, which are fully implemented modules.
