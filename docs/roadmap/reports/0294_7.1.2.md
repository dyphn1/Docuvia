## Round 1 — Architecture & Design Review

**What the dashboard currently shows:**
The dashboard (`dashboard.tsx`) renders 5 stat cards (Projects, L1 Tags, L2 Nodes, L3 Nodes, Pending Reviews) plus a Recent Activity feed. It fetches data from `GET /dashboard` which performs count queries across 5 tables.

**What is missing — Pipeline Status Display:**
The dashboard has **no pipeline status section whatsoever**. Specifically:

1. **No project status breakdown** — The `projectsTable` has a `status` column with values `active`, `indexing`, `paused`, `error`. The dashboard does not query or display how many projects are in each state. A Project Manager cannot see at a glance if any project is stuck in `indexing` or has entered `error` state.

2. **No last ingest/generate timestamps** — The `projectsTable` has `lastGitIngestedAt` and `lastSvnRevision` columns. None of this is surfaced on the dashboard.

3. **No pending commit counts** — The `IngestStatusCard` component (which shows VCS type, last sync time, and pending commit count) exists in the codebase but is **only used on the project detail page** (`projects/[id].tsx`), not on the dashboard.

4. **No pipeline health indicator** — There is no visual indicator (badge, alert, or status bar) showing whether the ingest/generate pipelines are healthy, running, or failed across projects.

5. **DashboardStats schema has no pipeline fields** — The OpenAPI `DashboardStats` schema and the generated `DashboardStats` TypeScript interface contain only aggregate counts and activity. No pipeline-related fields exist in the API contract.

**What exists elsewhere:**
- The dedicated Pipeline page (`/pipeline`) has a full project selector with status badge, ingest form, and generate form with loading/result/error states.
- The `IngestStatusCard` component shows VCS type, last sync cursor, and pending commit count — but only on the project detail page.
- The project detail page (`/projects/:id`) shows the project status badge and L2/L3 counts.

**Architecture Assessment:** The pipeline status data is available in the DB and partially rendered on other pages, but it is completely absent from the dashboard. The dashboard page, backend route, and OpenAPI spec would all need updates to support this.

## Round 2 — Code Quality & Security Review

**Findings:**

1. **DashboardStats schema is incomplete for the stakeholder requirement** — The `DashboardStats` schema at `openapi.yaml:1673` defines 6 fields (totalProjects, totalL1Tags, totalL2Nodes, totalL3Nodes, pendingReviews, recentActivity). It is missing pipeline status fields such as:
   - `projectsByStatus`: breakdown of projects by status (active, indexing, paused, error)
   - `lastIngestAt`: most recent ingest timestamp across all projects
   - `runningPipelines`: count of projects currently in `indexing` state

2. **Backend route doesn't query project status** — `routes/dashboard.ts` performs 5 count queries but none of them group by `projectsTable.status`. A simple `SELECT status, COUNT(*) FROM projects GROUP BY status` would provide the needed data.

3. **Frontend doesn't render any pipeline UI** — `dashboard.tsx` has no pipeline-related JSX, no status badges for pipeline health, and no section heading for pipeline status.

4. **IngestStatusCard is reusable but not reused** — The `IngestStatusCard` component accepts a `projectId` prop and shows pipeline status for a single project. It could be adapted for dashboard use (e.g., showing a summary card per project), but it is currently only used in `projects/[id].tsx`.

5. **No test coverage** — As noted in the 7.1.1 report, there are zero tests for the dashboard frontend or backend. This applies equally to any pipeline status display that would be added.

## Gaps & Recommendations

1. **Add project status breakdown to dashboard backend** — Add a `SELECT status, COUNT(*) FROM projects GROUP BY status` query to `routes/dashboard.ts` and include the result in the response.

2. **Extend DashboardStats schema** — Add a `projectsByStatus` field (or individual count fields like `activeProjects`, `indexingProjects`, `errorProjects`) to the `DashboardStats` schema in `openapi.yaml`, then run codegen.

3. **Add pipeline status section to dashboard frontend** — Add a visually distinct section to `dashboard.tsx` showing project status breakdown with color-coded badges (green for active, amber for indexing, red for error). Consider also showing the most recent ingest timestamp.

4. **Consider surfacing IngestStatusCard on dashboard** — Either embed a summary version of `IngestStatusCard` on the dashboard or create a new dashboard-specific component that aggregates pipeline health across all projects.

5. **Add test coverage** — Once implemented, add integration tests for the updated `GET /dashboard` endpoint and component tests for the new pipeline status UI.
