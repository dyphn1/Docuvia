## Round 1 — Architecture & Design Review

**What 7.3.2 requires ("Query result display with strategy indicator"):**

The checklist item has two parts:
1. **Query result display** — Show search results to the user
2. **Strategy indicator** — Display which routing strategy was used (vector_search, graph_traversal, direct_lookup, hybrid)

**Backend implementation:**

The `POST /mcp/query` handler (mcp.ts:236-253) calls `routeQuery()` which returns a `RouteQueryResult` containing:
- `routingStrategy`: The top-level strategy used (`vector_search` | `graph_traversal` | `direct_lookup` | `hybrid`)
- `results[]`: Each result has a `source` field (`"vector"` | `"graph"` | `"direct"`)
- `metadata.classificationConfidence` and `metadata.reasoning`
- `entities`: Extracted module name, commit hash, search query

The OpenAPI spec (`McpQueryResult`, line 2575) correctly declares `routingStrategy` as a required field with the `RoutingStrategy` enum.

**Frontend implementation (query.tsx):**

The frontend has a `SearchResponse` interface (lines 28-31):
```typescript
interface SearchResponse {
  results: SearchResultItem[];
  total: number;
}
```

This interface is **missing**:
- `routingStrategy` — the top-level strategy indicator
- `entities` — extracted entities
- `metadata` — classification confidence, reasoning, durationMs
- Per-result `source` field — each `AgenticSearchResult.source` is not mapped to `SearchResultItem`

The `SearchResultItem` interface (lines 17-26) has `nodeLayer` but **no `source` field** to distinguish vector vs graph vs direct results.

The results rendering (lines 166-199) only displays:
- Layer badge (L1/L2/L3) with color coding
- Project name
- Score
- Title and content

**There is NO strategy indicator anywhere in the UI.** No badge, no label, no icon showing whether the query used vector search, graph traversal, direct lookup, or hybrid routing.

**Additionally, the frontend has a request body mismatch** (same class of bug as 7.3.1):
- Frontend sends: `{ query, projectId, limit }` (line 68-72)
- Backend Zod schema expects: `{ q, project_id, limit }` (mcp.ts:230-234)
- This means **every query will fail with 400 "q is required"** unless the query somehow bypasses Zod validation

The frontend also **sends no `Authorization` header** (line 67), while the backend requires `Bearer ${MCP_PAT}` (mcp.ts:20-36).

## Round 2 — Code Quality & Security Review

**Findings:**

1. **[CRITICAL] Request body field name mismatch** — `query.tsx` sends `{ query, projectId, limit }` but `mcp.ts` Zod schema expects `{ q: z.string().min(1), project_id: z.number(), limit: z.number() }`. Every POST to `/api/mcp/query` will return 400 Bad Request with `"q is required"`. The query functionality is **completely non-functional** through the official MCP POST endpoint.

2. **[CRITICAL] No Authorization header** — The `fetch()` call at line 65-72 has no `Authorization` header. Even if the field names matched, the request would fail with 401 Unauthorized (when `MCP_PAT` is set) or 500 (when unset).

3. **[HIGH] Strategy indicator completely absent** — The `SearchResponse` interface lacks `routingStrategy`, `entities`, and `metadata`. The result cards show layer badges (L1/L2/L3) and scores but no indication of which search strategy produced them. This is the core gap for this checklist item.

4. **[HIGH] Per-result `source` field not mapped** — Each `AgenticSearchResult` has a `source` field (`"vector"` | `"graph"` | `"direct"`) that distinguishes how each individual result was found. The frontend `SearchResultItem` has no `source` field. Even if the top-level strategy were displayed, per-result attribution would still be missing.

5. **[MEDIUM] Frontend uses raw fetch() instead of generated hooks** — The codebase generates React Query hooks from the OpenAPI spec. The query page should use a generated `useMcpQuery`_hook (if it exists in `lib/api-client-react/src/generated/api.ts`) for automatic cache management and error handling. Raw `fetch()` bypasses the generated API layer.

6. **[LOW] Empty results UI is good** — The empty state (lines 154-163) shows a helpful message with the query text and a suggestion to run the pipeline. This is well-implemented.

7. **[LOW] Score display is present** — Result cards show `score: {item.score.toFixed(2)}` (line 187), which is a useful quality signal.

**Security note:** The unauthenticated fetch to `/api/mcp/query` is a security gap (same as 7.3.1), but since the MCP auth middleware blocks it, the practical risk is limited to the 401 response.

**Strategy indicator gap analysis:**

The `routeQuery()` function (intent-router.ts:614-740) produces:
- `routingStrategy`: One of `"vector_search"`, `"graph_traversal"`, `"direct_lookup"`, `"hybrid"` (line 731)
- Each result's `source`: One of `"vector"`, `"graph"`, `"direct"` (e.g., line 232)
- `metadata.reasoning`: Human-readable explanation (line 736)

The frontend displays **none of these**. To implement the strategy indicator, the frontend would need to:
1. Add `routingStrategy: string` and `metadata: { reasoning: string }` to `SearchResponse`
2. Add `source: string` to `SearchResultItem`
3. Display a strategy badge (e.g., "🧭 Vector Search" or "🔗 Graph Traversal") in the results header
4. Optionally show per-result source icons

## Gaps & Recommendations

1. **[CRITICAL] Fix request body field names** — Change `query.tsx` line 68-72 from `{ query, projectId, limit }` to `{ q, project_id, limit }` to match the `mcpQueryBodySchema` Zod schema in `mcp.ts:230-234`.

2. **[CRITICAL] Add Authorization header** — Add `Authorization: Bearer ${MCP_PAT}` to the fetch call headers (same pattern needed as 7.3.1). Store `MCP_PAT` in env or config.

3. **[HIGH] Display routing strategy indicator** — Add `routingStrategy: RoutingStrategy` and `metadata: { classificationConfidence, reasoning, durationMs }` to the `SearchResponse` interface. Display a strategy badge in the results header (e.g., "🧭 Vector Search" or "🔗 Graph Traversal" or "🔍 Direct Lookup" or "⚡ Hybrid"). Use color-coded badges consistent with the layer badge pattern at lines 173-179.

4. **[HIGH] Display per-result source indicators** — Add `source: "vector" | "graph" | "direct"` to `SearchResultItem`. Show a small icon or label on each result card indicating how it was found (complements the layer badge).

5. **[MEDIUM] Switch to generated React Query hooks** — Import the generated mutation hook for `POST /mcp/query` from `@workspace/api-client-react` instead of raw `fetch()`. This provides automatic cache management and aligns with the project's API-first architecture.

6. **[LOW] Show metadata reasoning** — Optionally display `metadata.reasoning` as a tooltip or subtitle to help users understand why the system chose a particular strategy.
