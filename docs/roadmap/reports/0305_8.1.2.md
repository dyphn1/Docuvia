## Round 1 — Architecture & Design Review

### Design Intent

The spec (`nodes.md` §5) defines an "Unassigned Decisions" virtual node at Level 1 (direct child of the Project node) that groups L3 entries not yet assigned to an L2 module. The node must:

1. Appear as a child of the Project node (alongside L1 tags)
2. Use icon `$(question)` and context value `unassigned-group`
3. Be auto-created when any decision has `l2_module_id: unassigned` or references a non-existent L2 module
4. Expand to show unassigned L3 Entry nodes
5. Support drag-and-drop re-assignment to L2 modules
6. Provide a context menu action for AI-powered auto-categorization

### Implementation Analysis

**`KnowledgeGraphTreeProvider.ts`** (the core file):

- **`KGNodeKind` type** (line 8): `'unassigned-group'` is included in the union type — ✅
- **`getChildren()` for `project` nodes** (lines 202–214):
  - Builds `validModuleIds` set from `snap.modules` for O(1) lookup — ✅
  - Computes `hasUnassigned` by scanning `snap.decisions` for `d.l2_module_id === 'unassigned'` or IDs not in `validModuleIds` — ✅
  - Appends `unassigned-group` node to `tagChildren` only when `hasUnassigned` is true (conditional creation) — ✅
- **`getChildren()` for `unassigned-group` nodes** (lines 231–245):
  - Guards against missing snapshot (`if (!snap) return []`) — ✅
  - Filters decisions where `l2_module_id === 'unassigned'` or ID not in `validModuleIds` — ✅
  - Maps them to `l3entry` KGNode objects with `filePath` and `workspaceRoot` — ✅
- **`getTreeItem()` for `unassigned-group`** (lines 89–93):
  - Creates `TreeItem` with `Collapsed` state (expandable) — ✅
  - Uses `ThemeIcon('question')` — ✅
  - Sets `contextValue = 'unassigned-group'` — ✅
- **Drag-and-drop** (lines 37–81):
  - `handleDrag` filters for `l3entry` nodes and sets the data transfer — ✅
  - `handleDrop` validates `l2module` target, checks `workspaceRoot` match, updates `l3_router.yaml` — ✅

**`extension.ts`** (wiring):

- TreeView created at line 56 with `treeDataProvider: kgProvider` and `dragAndDropController: kgProvider` — ✅
- `docuvia.autoCategorizeDecisions` command registered at line 132, retrieves children via `kgProvider.getChildren(node)` — ✅

**`package.json`** (menus):

## Round 2 — Code Quality & Security Review

### Code Quality Findings

1. **Defensive design in `getChildren` for `unassigned-group`** (lines 231–245): Properly guards against missing snapshot, uses `Set` for O(1) module ID lookup, handles both `'unassigned'` string sentinel and unmapped IDs. ✅

2. **Conditional node creation**: The `unassigned-group` node is only appended when `hasUnassigned` is true. No empty/unused node is shown when all decisions are properly assigned. ✅

3. **Context value consistency**: The `contextValue` set in `getTreeItem` (`'unassigned-group'`) matches the `when` clause in `package.json` (`viewItem == unassigned-group`) and the `KGNodeKind` type. ✅

4. **Type safety**: The `l2_module_id` field in `L3DecisionFrontmatterSchema` is typed as `z.string()` (line 44 of `types.ts`), which accepts the `'unassigned'` sentinel string. The `L3RouterEntrySchema` also uses `z.string()` for `l2_module_id`. ✅

5. **No circular dependencies**: `KnowledgeGraphTreeProvider` imports from `KnowledgeStore` which does not import back. Clean unidirectional dependency. ✅

6. **Auto-categorization flow**: When `docuvia.autoCategorizeDecisions` is invoked (extension.ts line 132), `kgProvider.getChildren(node)` correctly returns unassigned L3 entries since `getChildren` handles `unassigned-group` kind. The task receives `workspaceRoot` from the KGNode. ✅

### Test Coverage

No dedicated unit tests exist for `KnowledgeGraphTreeProvider`. There are no test files under `artifacts/vscode-client/`. This is consistent with the broader pattern where VS Code extension UI logic lacks isolated unit tests (checklist items 9.4.3–9.4.5 note E2E tests are "not done").

🟡 Medium: No unit tests for `KnowledgeGraphTreeProvider.getChildren()` logic, particularly the unassigned-group detection and filtering edge cases.

### Security

- The TreeProvider reads exclusively from the local `.docuvia/` directory and in-memory snapshot — no external user input is processed. ✅
- No XSS or injection vectors: VS Code TreeItem labels are rendered by the host, not as HTML. ✅

### Edge Case Analysis

| Edge Case                                       | Handling                                                                                              | Status |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ------ |
| No decisions at all                             | `hasUnassigned` = false, no unassigned-group shown                                                    | ✅     |
| All decisions assigned                          | `hasUnassigned` = false, no unassigned-group shown                                                    | ✅     |
| All decisions unassigned                        | `hasUnassigned` = true, all entries under unassigned-group                                            | ✅     |
| Mixed assigned/unassigned                       | Only unassigned entries appear under unassigned-group                                                 | ✅     |
| `l2_module_id` references nonexistent L2 module | Detected via `!validModuleIds.has(d.l2_module_id)`                                                    | ✅     |
| Empty `l2_module_id` string                     | Not explicitly handled — would be treated as unmapped (included in unassigned)                        | 🟢 Low |
| Snapshot missing for workspace root             | `if (!snap) return []` guard                                                                          | ✅     |
| Drag-and-drop to unassigned-group               | `handleDrop` requires `target.kind === 'l2module'` — drops on unassigned-group are rejected (correct) | ✅     |
| Multi-root workspace with mixed states          | Each workspace root has its own snapshot; unassigned-group appears independently per project          | ✅     |

### End-to-End Flow

1. **Data flow**: `KnowledgeStore.load()` → parses `.docuvia/l3_decisions/*.md` → populates `KnowledgeGraphSnapshot.decisions` Map → `KnowledgeGraphTreeProvider.getChildren()` reads from snapshot → unassigned-group appears when applicable ✅
2. **TreeView registration**: `extension.ts` creates `KnowledgeGraphTreeProvider`, passes to `createTreeView` ✅
3. **Context menu**: `package.json` declares `docuvia.autoCategorizeDecisions` on `view/item/context` with `when: viewItem == unassigned-group` ✅
4. **Auto-categorization action**: `TaskRunner.queueAutoCategorization()` creates async task with LM-based classification ✅
5. **Refresh mechanism**: `KnowledgeStore.onDidLoad` event triggers `KnowledgeGraphTreeProvider.refresh()` via constructor subscription (line 34) ✅
6. **Drag-and-drop re-assignment**: User drags L3 entry to L2 module → `handleDrop` updates `l3_router.yaml` → calls `store.load()` → tree refreshes ✅

### Performance

- Unassigned detection iterates all decisions once: O(D) where D = number of decisions. Acceptable for typical project sizes.
- Module ID lookup uses `Set`: O(1) per decision.
- No unnecessary re-renders: `onDidChangeTreeData` fires only on explicit `refresh()` calls triggered by store load events.
