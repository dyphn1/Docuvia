## Round 1 — Architecture & Design Review

The DashboardPanel is a VS Code WebviewPanel that provides an embedded dashboard showing knowledge graph health, extraction queue status, and recent decisions.

**Registration flow:**

1. `package.json:68-71` declares `docuvia.openDashboard` with title `"Docuvia: Open Dashboard"` and `$(home)` icon
2. `extension.ts:158-182` registers the command handler, which resolves the target workspace root (from node argument, single-folder auto-detect, or multi-folder picker) and calls `DashboardPanel.createOrShow()`
3. `package.json:166-169` adds the command to the Knowledge Graph view title navigation menu (`view == docuvia.knowledgeGraph`)

**Panel lifecycle:**

1. `DashboardPanel.createOrShow()` checks for an existing panel per workspace root (`_panels` Map keyed by `targetRoot`); if one exists, it reuses it
2. A new `vscode.window.createWebviewPanel` is created with `enableScripts: true`, `retainContextWhenHidden: true`, and `localResourceRoots` scoped to the extension's `out/` directory
3. The constructor sets initial HTML, pushes initial data, subscribes to `store.onDidLoad`, registers the webview message handler, and registers the dispose handler
4. On dispose: the `onDidLoad` subscription is cleaned up and the panel is removed from the `_panels` Map

**Architecture assessment:** The panel follows a clean singleton-per-root pattern. The separation between the static `createOrShow` factory and the instance methods is well-structured. The `DashboardPayload` interface matches the design spec exactly. No architectural gaps found.

## Round 2 — Code Quality & Security Review

**Command registration** (`extension.ts:158-182`):

- Accepts optional `node` parameter with `workspaceRoot` property for tree view invocations
- Multi-root workspace support: auto-detects for single-folder, shows `showWorkspaceFolderPick` for multi-folder
- Early return with warning message if no workspace is open
- Clean delegation to `DashboardPanel.createOrShow()` with all required dependencies (`context`, `store`, `targetRoot`, `tqProvider`)

**Webview security:**

- Nonce-based CSP: `randomBytes(16)` generates a unique nonce per panel creation
- CSP restricts `style-src` and `script-src` to nonce-only, `default-src 'none'`
- `localResourceRoots` scoped to extension `out/` directory only
- `enableScripts: true` is required for the message protocol and is properly protected by the nonce CSP

**Path validation** (`DashboardPanel.ts:157-164`):

- The `_handleMessage` method validates that `msg.filePath` starts with the workspace root before opening
- Paths outside the workspace are silently rejected — matches the design spec exactly
- The `openDecision` message type checks `typeof msg.filePath === 'string' && msg.filePath.length > 0`

**HTML escaping:**

- `escapeHtml()` function escapes `&`, `<`, `>`, `"` — prevents XSS in decision titles and module names
- `escapeAttr()` function escapes `"` and `'` for attribute values
- Both are used in the client-side rendering code

**Theming:**

- All CSS uses VS Code native variables: `--vscode-font-family`, `--vscode-editor-foreground`, `--vscode-editor-background`, `--vscode-panel-border`, `--vscode-sideBarSectionHeader-background`, `--vscode-editorWidget-background`, `--vscode-descriptionForeground`, `--vscode-badge-background`, `--vscode-badge-foreground`, `--vscode-textLink-activeForeground`, `--vscode-input-background`, `--vscode-input-placeholderForeground`, `--vscode-input-border`, `--vscode-focusBorder`
- No hardcoded colors — fully theme-compliant

**Data flow:**

- `buildDashboardPayload()` is a pure function that transforms a `KnowledgeGraphSnapshot` into a `DashboardPayload`
- Graceful null handling: returns zeroed payload when snapshot is null/undefined
- `recentDecisions` sorted by date descending, limited to 5
- `topModules` sorted by decision count descending, limited to 5
- Task counts come from `TaskQueueTreeProvider.getPendingCount()` / `getInProgressCount()`

**Memory management:**

- `onDidLoad` subscription is disposed in the `onDidDispose` handler
- Panel is removed from `_panels` Map on dispose
- No event listener leaks

**Code quality:**

- Clean separation of concerns: pure helper (`buildDashboardPayload`), message handling, HTML building
- Consistent use of TypeScript access modifiers (`private`, `readonly`)
- The `_panels` static Map provides proper singleton-per-root semantics
- Panel title includes workspace name for multi-root clarity

## Round 3 — Integration & Completeness Review

**End-to-end flows:**

1. User opens command palette → "Docuvia: Open Dashboard" → `docuvia.openDashboard` fires → workspace root resolved → `DashboardPanel.createOrShow()` → panel opens with data
2. User clicks `$(home)` icon in Knowledge Graph view title bar → same command fires → same flow
3. If a panel for that workspace root already exists → `reveal()` brings it to front and pushes fresh data
4. On `store.onDidLoad` event → panel automatically refreshes with latest snapshot data
5. User clicks a decision in the list → `openDecision` message sent → extension validates path → opens document
6. User clicks "Ask Docuvia…" button → `openChat` message sent → Copilot Chat opens with `@docuvia`
