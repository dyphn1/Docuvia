## Round 1 — Architecture & Design Review

**What the spec says:**
The `docuvia.addDecision` command should: resolve the initialized workspace → prompt for title → QuickPick L2 module → generate L3 markdown with frontmatter → write to `.docuvia/l3_decisions/{slug}.md` → reload KnowledgeStore → open the file in the editor. A variant `addDecisionFromSelection` additionally captures the active text selection and pre-fills it as a code block in the Context section.

**What the code does:**
Both commands are registered in `extension.ts` but their handler bodies are empty:

- `extension.ts:159-161`: `docuvia.addDecision` handler body is `// await addDecision(context, store);` — the actual call is commented out
- `extension.ts:264-275`: `addDecisionFromSelection` captures selected text correctly (lines 265-272) but then calls `// await addDecision(context, store, prefillBody);` — also commented out

**Critical finding:** There is no `addDecision` function defined anywhere in the codebase (`grep` across all `.ts` files under `src/` returns zero function definitions). The design spec documents a full 6-step workflow, but the implementation is non-functional — the command registers successfully in VS Code but does nothing when invoked.

**Gap analysis:**
- ❌ Workspace resolution logic — not implemented
- ❌ Title input box — not implemented
- ❌ L2 module QuickPick — not implemented
- ❌ L3 markdown generation with frontmatter — not implemented
- ❌ File write to `.docuvia/l3_decisions/` — not implemented

## Round 2 — Code Quality & Security Review

The current code has no security surface since it does nothing. However, the design docs list known bugs that would need to be addressed in a complete implementation:

- **Slug collision** (BUG C-3 / BUG I-3): No check for existing files — same-title decisions would silently overwrite
- **Uninitialized workspace** (Journey C/I Bad Cases): Behavior when `.docuvia/` is not initialized is unverified — the design says it should block but the implementation would fail silently
- **Special-character titles** (`!!!`): Slug generation could produce empty slug → path `.docuvia/l3_decisions/.md`
- **`l3_router.yaml` not updated** (BUG C-1 / BUG I-1): Design doc lists this as a known issue even for the "intended" implementation — decisions would be invisible to CodeLens/Hover until reload

**Code quality assessment:** The commented-out calls suggest this was intentionally stubbed. The `addDecisionFromSelection` handler correctly validates selection and captures text before the stub — showing the architecture was designed before being disabled. No lint issues in the existing code.

The infrastructure exists; the implementation function is simply missing.

## Gaps & Recommendations

1. **Implement `addDecision` function** — The entire function body needs to be written. The design spec at `design/command-palette/add-decision.md` provides the complete algorithm. This is the primary blocker.

2. **Uncomment handler calls in `extension.ts:160` and `:273`** — Once the function exists, uncomment the calls or inline the logic directly in the handler.

3. **Add slug collision check** — Before writing, verify no existing file has the same slug. Prompt user to overwrite or rename.

4. **Validate workspace initialization** — Block with "Initialize Docuvia first" if `.docuvia/` is not initialized in the target workspace.

5. **Handle special-character titles** — Validate slug is non-empty after sanitization.

6. **Append to `l3_router.yaml`** — The design doc's known bugs (BUG C-1/I-1) note this gap even in the intended implementation. Address it to make decisions visible to CodeLens/Hover.

7. **Add tests** — At minimum, verify: title input → file creation with correct frontmatter, workspace resolution, uninitialized workspace error.

8. **Consider hiding commands from package.json** — Until implemented, these commands should be removed from `package.json` to avoid user confusion, OR a placeholder message ("This feature is coming soon") should be shown.
