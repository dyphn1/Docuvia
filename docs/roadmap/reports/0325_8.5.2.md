## Round 1 — Architecture & Design Review

**Panel creation flow:**
1. `docuvia.openSearch` (line 354) prompts user via `showInputBox`, then calls `executeSearch()`
2. `docuvia.searchFromSelection` (line 365) reads editor selection, caps at 2000 chars (BUG N-2 fix at line 371), then calls `executeSearch()`
3. `executeSearch()` (line 387) reads `docuvia.search.defaultView` setting: `'chat'` (default) opens Copilot Chat; `'webview'` calls `centralClient.query()` and opens `SearchResultsPanel`
4. `SearchResultsPanel.createOrShow()` (line 12) implements singleton pattern — reuses existing panel or creates new one
5. Constructor (line 40) sets HTML, registers `onDidReceiveMessage` handler, registers dispose handler

**Architecture assessment:**
- Clean singleton pattern via static `_current` field
- Proper panel lifecycle: `onDidDispose` clears the static reference (line 57-63)
- `pushResults()` (line 66) allows updating an existing panel with new results
- The `CentralSearchResult` interface (title, projectName, l1Tags, snippet, score) is well-typed
- `CentralServerClient.query()` returns `[]` when no `server_url` is configured (line 59-61) — this means the panel opens but shows "No cross-project results found" with no indication that the server is not configured (design doc BUG N-1 at `user-journeys.md:513`)

**Stale conflict note in design spec:**
The `webview-panels.md:17-23` conflict note claims three gaps: (1) no grouping, (2) no keyword highlighting, (3) no click-to-navigate. All three have been implemented:
- Grouping by `projectName` at lines 99-105
- `<mark>` keyword highlighting via `highlightKeywords()` at lines 91-97
- `enableScripts: true` at line 31, `acquireVsCodeApi()` at line 215, click-to-chat at line 216-218
The conflict note is **stale** and should be removed from the design doc.

## Round 2 — Code Quality & Security Review

**Webview security:**
- Nonce-based CSP at line 142-143: `default-src 'none'; style-src ${cspSource} 'nonce-${nonce}'; script-src 'nonce-${nonce}';`
- `localResourceRoots` scoped to extension `out/` directory (line 32)
- `retainContextWhenHidden: true` (line 33) — correct for a results panel
- Nonce generated via `randomBytes(16)` (line 81) — cryptographically secure

**XSS prevention:**
- `escapeHtml()` (lines 84-89) escapes `&`, `<`, `>`, `"` — used on all dynamic content (title, projectName, tags, query display)
- `JSON.stringify(r.title)` used for the `onclick` handler attribute (line 123) — safe against injection

**Message protocol:**
- Single message type: `openResult` with `title` string payload (line 73)
- Clicking a result opens Copilot Chat with `@docuvia /query <title>` (line 74-76)
- Keyboard accessibility: Enter/Space triggers click (lines 219-223)

**BUG N-2 fix (query length cap):**

- This fix is implemented but the design doc `user-journeys.md:503` still lists it as a known issue — stale doc

**BUG N-1 (no local fallback):**

**No server configured behavior:**

## Gaps & Recommendations

1. **BUG N-1 — No local fallback (Medium):** When `defaultView` is `'webview'` and the server is unavailable, the user gets a generic error. Consider falling back to local knowledge search (via `KnowledgeStore`) when the central server fails, similar to how the chat path handles it.

2. **No server configured UX (Medium):** When `server_url` is not set, the panel opens empty with no indication of what's wrong. Add a helpful message like "Server not configured. Set `server_url` in `~/.docuvia/config.yaml`." in the webview HTML when the result is empty and no server is configured.

3. **No test coverage (Low):** Add unit tests for the `escapeHtml()` and `highlightKeywords()` helper functions, and an integration test for the `executeSearch` → `SearchResultsPanel` flow. The `buildDashboardPayload()` pure function in DashboardPanel is a good testing pattern to follow.

4. **Stale design docs (Low):** Remove the conflict note from `webview-panels.md:17-23` (all 3 gaps are fixed). Mark BUG N-2 as resolved in `user-journeys.md:503`.
