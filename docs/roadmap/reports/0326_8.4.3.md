## Round 1 — Architecture & Design Review

**What the spec says:**
The `docuvia.addDecision` command should implement a 6-step workflow:
1. Resolve the initialized workspace (prefer active editor's workspace, fall back to QuickPick if multiple, error if none)
2. Prompt user for a decision title via `showInputBox`; generate UUID and slug
3. QuickPick L2 modules from `store.snapshot.modules` + "unassigned" option
4. Generate L3 markdown with YAML frontmatter (id, l2_module_id, title, date, status)
5. Write to `.docuvia/l3_decisions/{slug}.md`
6. Call `store.load()` to reload KnowledgeStore, then open the file in the editor

The `addDecisionFromSelection` variant captures the active text selection, wraps it in a fenced code block, and passes it as `prefillBody` to step 4.

**What the code does:**
Both commands are registered in `extension.ts` but their handler bodies are empty stubs:

- `extension.ts:159-161`: `docuvia.addDecision` handler body is `// await addDecision(context, store);` — commented out
- `extension.ts:264-275`: `addDecisionFromSelection` captures selected text correctly (lines 265–272) but then calls `// await addDecision(context, store, prefillBody);` — also commented out

**Critical finding:** There is no `addDecision` function defined anywhere in the codebase. A grep across all `.ts` files under `src/` returns zero function definitions — only the two commented-out call sites in `extension.ts`. The command registers successfully in VS Code but is a silent no-op when invoked.

## Round 2 — Code Quality & Security Review

**Current code quality:**
The commented-out calls suggest this was intentionally stubbed during development. The `addDecisionFromSelection` handler correctly validates the selection (checks `editor.selection.isEmpty`) and captures text/language before the stub — showing the architecture was designed before being disabled. No lint issues in the existing code.

**Security surface:**
The current code has no security surface since it does nothing. However, the design docs list known bugs that would need addressing in a complete implementation:

- **Slug collision** (BUG I-3): No check for existing files — same-title decisions would silently overwrite
- **Uninitialized workspace**: Behavior when `.docuvia/` is not initialized is unverified — design says it should block with "Initialize Docuvia first"
- **Special-character titles** (`!!!`): Slug generation could produce empty slug → path `.docuvia/l3_decisions/.md`
- **`l3_router.yaml` not updated** (BUG I-1): Even the intended implementation doesn't append to the router — decisions would be invisible to CodeLens/Hover until file-system watcher triggers reload
- **`l2_module_id: "unassigned"` sentinel** (BUG I-2): Non-UUID string sentinel could cause downstream systems to skip/reject

**Dependency chain assessment:**
The infrastructure for a complete implementation exists:
- `KnowledgeStore` — singleton with `load()` method, functional and used by other commands
- `store.snapshot.modules` — L2 module list available for QuickPick
- `vscode.workspace.fs.writeFile` — standard API for file creation
- `vscode.window.showInputBox` / `showQuickPick` — standard APIs for user input
- `KnowledgeStore.load()` for reload — exists and tested by other commands

The implementation function is simply missing.

## Gaps & Recommendations

1. **CRITICAL — Implement `addDecision` function:** The entire function body needs to be written. The design spec at `design/command-palette/add-decision.md` provides the complete 6-step algorithm. This is the primary blocker.

2. **Uncomment handler calls in `extension.ts:160` and `:273`:** Once the function exists, uncomment the calls or inline the logic directly in the handlers.

3. **Add slug collision check (BUG I-3):** Before writing, verify no existing file has the same slug. Prompt user to overwrite or rename.

4. **Validate workspace initialization:** Block with "Initialize Docuvia first" if `.docuvia/` is not initialized in the target workspace.

5. **Handle special-character titles:** Validate slug is non-empty after sanitization — reject titles with no alphanumeric characters.

6. **Ensure `l3_decisions/` directory exists:** Create the directory before writing if it doesn't exist (VS Code's `writeFile` throws `FileNotFound` otherwise).

7. **Append to `l3_router.yaml` (BUG I-1):** The design doc's known bugs note this gap even for the intended implementation. Address it to make decisions visible to CodeLens/Hover without waiting for a file-system watcher reload.

8. **Add tests:** At minimum, verify: title input → file creation with correct frontmatter, workspace resolution, uninitialized workspace error, slug collision handling.

9. **Consider hiding commands from package.json until implemented:** These registered-but-no-op commands create user confusion. Either remove them from `package.json` until the implementation is ready, or show a placeholder message ("This feature is coming soon").
