## Round 1 — Architecture & Design Review

### Design Intent

The design spec (section 7.4) mandates a dedicated `lint` job in GitHub Actions that runs `pnpm prettier --check .` on every push to any branch and on every PR. The job runs in parallel with `typecheck-and-build`. The runtime environment should be `ubuntu-latest` with Node.js 24.x and pnpm 9.x.

Additionally, section 8.3 specifies that code style rules should be enforced by Prettier with `tabWidth: 4` and `printWidth: 100`, and that `eslint.config.js` should encode rules like `max-lines-per-function` and `max-len`.

### Implementation Analysis

**CI Workflow (`.github/workflows/ci.yml`):**
- ✅ The `lint` job is defined at line 21 as the first job
- ✅ It runs `pnpm run lint` (line 43), which maps to `prettier --check .`
- ✅ Triggered on push to `main`/`dev` and PRs to `main`/`dev` (lines 3-11)
- ✅ Uses `ubuntu-latest` runner (line 23)
- ✅ Node.js 24 configured (line 36)
- ✅ pnpm 9 via `pnpm/action-setup@v4` (lines 29-31)
- ✅ Uses `--frozen-lockfile` for reproducible installs (line 40)
- ✅ Runs in parallel with `typecheck-and-build` job

**Package Script (`package.json`):**
- ✅ `"lint": "prettier --check ."` defined at line 11
- ✅ `"format": "prettier --write ."` for auto-fix at line 12
- ✅ Prettier `^3.8.1` listed as devDependency (line 23)

**Prettier Configuration:**
- ❌ **No Prettier config file exists.** The design spec explicitly requires `tabWidth: 4` and `printWidth: 100`, but there is no `.prettierrc`, `.prettierrc.json`, `prettier.config.js`, or `prettier` key in `package.json`. Prettier defaults to `tabWidth: 2` and `printWidth: 80`.
- ❌ **No `eslint.config.js` exists.** The design spec mandates ESLint rules for `max-lines-per-function` and `max-len`, but no ESLint configuration file is present anywhere in the repository.
- ✅ `.prettierignore` exists and correctly excludes `node_modules/`, build outputs, Orval-generated code, lock files, and `attached_assets/`.

### Architecture Assessment

The CI workflow structure is well-designed — the lint job is properly defined, runs in parallel, and uses correct Node/pnpm versions. The workflow triggers are appropriate. However, the implementation is **incomplete** because the Prettier configuration is missing (no `tabWidth: 4` / `printWidth: 100` as specified in design docs), and the ESLint enforcement layer is entirely absent. The lint check currently **fails locally** with 35 files having formatting issues.

## Round 2 — Code Quality & Security Review

### Violations Found

1. **🔴 HIGH — Missing Prettier config (`tabWidth: 4`, `printWidth: 100`)** — The design doc at `docs/design/08-crosscutting-concepts.md:436` explicitly states: "The call-chain and indentation rules are enforced by Prettier with `tabWidth: 4` and `printWidth: 100`." No config file exists. Prettier defaults to `tabWidth: 2`, `printWidth: 80`. This means the lint job enforces **different formatting rules** than what the design spec mandates.

2. **🔴 HIGH — Missing `eslint.config.js`** — The design doc at `docs/design/08-crosscutting-concepts.md:436` states: "These rules should be encoded in `eslint.config.js` where tooling supports them (`max-lines-per-function`, `max-len`)." No ESLint config exists. The `max-lines-per-function` and `max-len` rules are completely unenforced.

3. **🟡 MEDIUM — `.prettierignore` does not exclude `.gitnexus/`** — Running `prettier --check .` warns about `.gitnexus/meta.json`, `.gitnexus/parse-cache/`, `.gitnexus/parsedfile-cache/`, and `.gitnexus/run.cjs`. These are tool-generated cache/index files that should be in `.prettierignore`. The `docs/archive_v1_design/` directory is also not excluded despite containing legacy files.

4. **🟡 MEDIUM — `.prettierignore` does not exclude `docs/roadmap/reports/`** — Multiple report files in `docs/roadmap/reports/` trigger formatting warnings. Since reports are generated by cron jobs and not meant to be manually formatted, they should be excluded.

5. **🟡 MEDIUM — 35 files currently fail lint check** — Running `pnpm run lint` locally produces `ELIFECYCLE Command failed with exit code 1` with "Code style issues found in 35 files." This means the CI lint job would fail if triggered on the current codebase state.

6. **🟢 LOW — `attached_assets/` in `.prettierignore` is a directory pattern without trailing slash** — Minor: `attached_assets/` works but `attached_assets` (without slash) would also match files named `attached_assets`.

### Positive Findings

1. ✅ **CI workflow structure is correct** — Proper job naming, parallel execution, correct triggers, proper action versions
2. ✅ **Frozen lockfile enforcement** — `--frozen-lockfile` prevents silent lockfile drift
3. ✅ **Node 24 alignment** — CI uses Node 24, matching production target (checklist 10.1.3 is marked as a "documented discrepancy" but the CI file itself correctly uses 24)
4. ✅ **`.prettierignore` correctly excludes generated code** — Orval-generated directories (`lib/api-zod/src/generated/`, `lib/api-client-react/src/generated/`) are excluded

### Test Coverage

No tests are relevant for this item — lint enforcement is a CI/build concern, not a runtime code concern.

## Recommendations

1. **[HIGH] Create Prettier config file** — Add `.prettierrc.json` (or `prettier.config.js`) with `{ "tabWidth": 4, "printWidth": 100 }` to match design spec requirements. This is the single most impactful fix.

2. **[HIGH] Create `eslint.config.js`** — Add flat ESLint config with `max-lines-per-function` and `max-len` rules as specified in `docs/design/08-crosscutting-concepts.md`.

3. **[MEDIUM] Update `.prettierignore`** — Add `.gitnexus/`, `docs/roadmap/reports/`, and `docs/archive_v1_design/` to prevent false positives from generated/archived files.

4. **[MEDIUM] Run `pnpm prettier --write .`** — Fix the 35 currently unformatted files so the CI lint job passes.

5. **[LOW] Consider adding `prettier --check` to pre-commit hook** — While not in the design spec, a pre-commit hook (via `husky` + `lint-staged`) would catch formatting issues before they reach CI.

---

## Overall Verdict

⚠️ **WARN** — The CI lint job is structurally well-defined in `.github/workflows/ci.yml` with correct triggers, runtime environment, and parallel execution. However, the implementation is incomplete: (1) No Prettier config file exists, violating the design spec's requirement for `tabWidth: 4` and `printWidth: 100`; (2) No `eslint.config.js` exists, leaving `max-lines-per-function` and `max-len` rules unenforced; (3) 35 files currently fail the lint check, meaning the CI job would fail if triggered. The CI infrastructure is in place, but the configuration layer that makes it meaningful is missing.
