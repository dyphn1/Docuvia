## Round 1 — Architecture & Design Review

### Design Intent

The design spec (section 7.4) defines a CI pipeline with two parallel jobs: `lint` and `typecheck-and-build`. The deployment considerations (section 7.5) explicitly acknowledge that "No `.vsix` build script in CI" exists and that `vsce package` must be run manually. The debt is tracked as D-02 (🟡 Medium).

The intended developer workflow is:
1. Developer runs `pnpm --filter @workspace/vscode-client run package` locally
2. This produces a `.vsix` file via `vsce package --no-dependencies`
3. The `.vsix` can be sideloaded via `code --install-extension`

### Implementation Analysis

**CI Workflow (`.github/workflows/ci.yml`):**
- ✅ `lint` job — formatting checks (would fail in current state, see 10.1.1)
- ✅ `typecheck-and-build` job — `pnpm run typecheck` + `pnpm -r --if-present run build`
- ✅ `test` job — Vitest with PostgreSQL
- ❌ **No `.vsix` packaging step** — CI never invokes `pnpm run package` in vscode-client
- ❌ **No artifact upload of `.vsix`** — no `actions/upload-artifact` step for .vsix

**Release Workflow (`.github/workflows/release.yml`):**
- ✅ Triggered on tags matching `v*`
- ✅ Runs `pnpm run build` then `cd artifacts/vscode-client && pnpm run package`
- ✅ Uploads `.vsix` to GitHub Release via `softprops/action-gh-release@v2`
- ⚠️ **Only triggered on version tags** — not on every push to `main`

**Extension `package.json` (`artifacts/vscode-client/package.json`):**
- ✅ `scripts.package: "pnpm run esbuild && vsce package --no-dependencies"` — correct
- ✅ `@vscode/vsce: "^3.9.2"` in devDependencies — packaging tool installed
- ✅ `engines.vscode: "^1.90.0"` — properly declared
- ✅ `publisher: "docuvia"` — publisher identity set

### Architecture Assessment

The CI pipeline is well-structured for core validation (lint, typecheck, build, test) but has a clear gap in artifact production. The `.vsix` file — the sole distributable artifact for the VS Code extension — is never produced in CI. This creates a dependency on manual developer action for packaging. Notably, a release workflow exists that DOES package the .vsix, but only on semantic version tags, not on regular pushes to main.

## Round 2 — Code Quality & Security Review

### Violations Found

1. **🟡 MEDIUM — CI does not produce `.vsix` artifact on push to `main`** — The `typecheck-and-build` job runs `pnpm -r --if-present run build`, which invokes the `build` script (tsc typecheck + emit), but does NOT invoke the `package` script (esbuild + vsce package). The `.vsix` file is not generated, not uploaded as a build artifact, and not available for download from CI. This is the core D-02 debt.

2. **🟡 MEDIUM — Missing extension metadata files** — `vsce package` expects `README.md` and `CHANGELOG.md` in the extension package directory. The `artifacts/vscode-client/` directory lacks both. Running `vsce package` produces warnings about missing files (though `--no-dependencies` bypasses dependency checks).

3. **🟡 MEDIUM — Release workflow is tag-gated, not push-gated** — The `release.yml` workflow correctly packages the .vsix but only triggers on `v*` tags. This means:
   - Every push to `main` produces NO .vsix artifact
   - Developers must manually create a GitHub Release with a version tag to get a .vsix
   - There's no CI validation that `vsce package` succeeds before a tag is created

4. **🟢 LOW — Compiled `out/` directory committed to repo** — `artifacts/vscode-client/out/extension.js` exists in the repo. This indicates the build was run manually at some point but these artifacts are not reproducible via CI (since the `package` script is never invoked).

5. **🟢 LOW — `private: true` in package.json** — Prevents accidental `vsce publish` but is intentional for pre-1.0 development.

### Positive Findings

1. ✅ **Release workflow exists** — Unlike many D-02 debt items, there IS a packaging mechanism in CI—it's just gated behind version tags
2. ✅ **Packaging script is correct** — `pnpm run esbuild && vsce package --no-dependencies` is the standard pattern
3. ✅ **vsce is installed** — `@vscode/vsce@^3.9.2` is in devDependencies
4. ✅ **esbuild bundling configured** — Properly bundles extension.ts into a single `out/main.js`
5. ✅ **Known debt is documented** — D-02 and R-07 explicitly acknowledge this gap
6. ✅ **GitHub Release upload configured** — `softprops/action-gh-release@v2` with glob pattern for `.vsix`

### Test Coverage

No tests are directly relevant for this item — the `.vsix` build is a CI/infrastructure concern, not a runtime feature.

## Recommendations

1. **[MEDIUM] Add CI packaging step on push to `main`** — Add a new job in `.github/workflows/ci.yml` that runs `pnpm --filter @workspace/vscode-client run package` after `typecheck-and-build` passes, and uploads the `.vsix` as a build artifact:
   ```yaml
   package-vsix:
     name: Package VS Code Extension
     runs-on: ubuntu-latest
     needs: [typecheck-and-build]
     if: github.ref == 'refs/heads/main'
     steps:
       - uses: actions/checkout@v4
       - uses: pnpm/action-setup@v4
         with: { version: 9 }
       - uses: actions/setup-node@v4
         with: { node-version: "24", cache: "pnpm" }
       - run: pnpm install --frozen-lockfile
       - run: pnpm --filter @workspace/vscode-client run package
       - uses: actions/upload-artifact@v4
         with:
           name: docuvia-vsix
           path: artifacts/vscode-client/*.vsix
   ```

2. **[MEDIUM] Add extension metadata files** — Create `artifacts/vscode-client/README.md` (extension description) and `artifacts/vscode-client/CHANGELOG.md`. These are required for clean `vsce package` execution.

3. **[LOW] Add `out/` to `.gitignore`** — The compiled output should be a CI artifact, not a committed file. Remove committed `artifacts/vscode-client/out/` files and add to `.gitignore`.

4. **[LOW] Document packaging workflow** — Add a note to `docs/design/07-deployment.md` explaining: (a) .vsix is automatically produced on push to main as a build artifact, (b) .vsix is attached to GitHub Releases when a `v*` tag is pushed.

## Overall Verdict

⚠️ **WARN** — The CI pipeline (`.github/workflows/ci.yml`) is structurally complete for core validation (lint, typecheck, build, test) but does not produce the `.vsix` distributable artifact on push to `main`. A separate release workflow (`.github/workflows/release.yml`) correctly packages the .vsix on version tags and uploads it as a release asset, which partially mitigates the D-02 debt. However, the gap remains: regular CI runs do not validate or produce the extension package, meaning packaging errors would only be caught when a developer manually creates a version tag. The extension `package.json` correctly defines the packaging script (`pnpm run esbuild && vsce package --no-dependencies`) and `@vscode/vsce` is installed, but metadata files (README.md, CHANGELOG.md) are missing. This is a known debt item (D-02, R-07) explicitly documented in `11-risks-and-debt.md`.
