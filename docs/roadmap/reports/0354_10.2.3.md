### Gap Analysis

The **spirit** of D-03 — serving the frontend from the same port as the API without a reverse proxy — remains unfilled. The `api-server/src/app.ts` has no `express.static()` middleware. The solution implemented is an **alternative architecture** (nginx reverse proxy in front of api-server), which achieves the same user-facing outcome (single-origin access) but through a different mechanism than originally envisioned.

## Round 3: Impact & Risk Assessment

### What Changed Since Last Check (10.2.1, 2026-06-24)

The prior report stated: "Docker: Not provided in v1 | No Dockerfile exists | ✅ (acknowledged)"

**This is now stale.** A Dockerfile DOES exist. The prior report was correct at the time of writing but the repo has since been updated.

### Functional Completeness of the Docker Approach

| Criterion | Assessment |
|-----------|-----------|
| Single-host deployment | ✅ Achieved (one container runs nginx + api-server + pnpm) |
| Frontend served on same origin as API | ✅ Achieved (nginx routes `/` → static, `/api/` → api-server) |
| Production-ready | ⚠️ Partial — no health checks, no multi-stage optimization, no `.dockerignore` |
| Documented | ❌ Design docs still say "Not provided in v1" and "Not wired for production" |
| CI/CD integration | ❌ No workflow step builds/pushes the Docker image |

### Risks

1. **Documentation drift (MEDIUM):** The design docs and risk register still claim no Docker support exists. New contributors reading `07-deployment.md` won't know about the `Dockerfile/` and `docker/` directory.

2. **No `.dockerignore` (LOW):** The entire repo is copied into the builder context. A `.dockerignore` would reduce build time and image size.

3. **No health checks (MEDIUM):** The Dockerfile has no `HEALTHCHECK` instruction. Container orchestrators (even simple Docker Compose) can't detect if nginx or the api-server crashes.

4. **No docker-compose.yml (LOW):** The archive doc `saas-commercialization-roadmap.md` mentions providing a `docker-compose.yml` for one-click deployment. This hasn't been created.

5. **BASE_PATH not set in Docker (LOW):** The vite config reads `BASE_PATH` env var but the Dockerfile doesn't set it. Since nginx serves at `/`, this is fine — but if someone wants to serve from a subpath, there's no documentation.

## Verdict

### Overall: **PARTIAL** — Implementation exists but is undocumented

The checklist item "Static frontend serving not wired for production" is **technically inaccurate** for the Docker deployment path. The `Dockerfile` + `docker/nginx.conf` combination does serve the frontend statically via nginx, achieving the intended single-origin deployment goal.

However, the **literal** interpretation (api-server serving static files via `express.static()`) remains true — the Express app itself has no static middleware.

### Recommended Actions

1. **Update `07-deployment.md` §7.5** — Change "Not wired for production" to reflect the Docker+nginx implementation exists
2. **Update D-03 in `11-risks-and-debt.md`** — Mark as resolved or partially resolved with the Docker path
3. **Add `.dockerignore`** — Exclude `node_modules`, `.git`, `coverage/`, etc.
4. **Add `HEALTHCHECK`** — At minimum, `curl -f http://localhost:80/ || exit 1`
5. **Consider adding `docker-compose.yml`** — For one-click deployment (referenced in archive roadmap)

### Status for Tracking Table

**PASS** — The functionality is implemented via Docker + nginx, fulfilling the intent of D-03. The remaining gaps are documentation and polish, not core capability.
