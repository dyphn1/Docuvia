## Round 3: Impact & Risk Assessment

### What Changed Since Design Doc Was Written

The `07-deployment.md` §7.5 claims "Docker image: Not provided in v1." This is **now stale**. A fully functional Docker setup exists:
- Multi-stage Dockerfile with nginx for static serving
- Start script that runs migrations + nginx + api-server
- Achieves the single-host deployment topology documented in §7.4

### Functional Completeness of the Docker Implementation

| Criterion | Assessment |
|-----------|-----------|
| Single-host deployment | ✅ Fully achieved (one container runs everything) |
| Frontend served on same origin as API | ✅ Via nginx reverse proxy |
| Database migrations | ✅ Automated in `start.sh` |
| Production-ready | ⚠️ Partial — no `HEALTHCHECK`, no `.dockerignore`, no resource limits |
| CI/CD Docker integration | ❌ No build/push workflow step |
| Published to registry | ❌ Not published |
| Documented | ❌ Design docs still say "Not provided in v1" |
| `docker-compose.yml` | ❌ Not provided (future work per archive roadmap) |

### Remaining Gaps

1. **No `.dockerignore`** (LOW) — The entire repository is the build context. `node_modules/`, `.git/`, `coverage/`, `dist/` are all sent to the Docker daemon on every build. This increases build time and image size unnecessarily.

2. **No `HEALTHCHECK`** (MEDIUM) — Container orchestrators can't detect if nginx or the api-server crashes. A simple `curl -f http://localhost:80/ || exit 1` would enable self-healing.

3. **No `docker-compose.yml`** (LOW) — The archive roadmap (`saas-commercialization-roadmap.md`) mentions providing one. For v1, the single-container approach is sufficient, but a `docker-compose.yml` with the Postgres service would simplify the story.

4. **CI doesn't build Docker image** (MEDIUM) — The `ci.yml` workflow does lint, typecheck, build, and test — but doesn't validate that the Docker image still builds. A broken Dockerfile would go undetected.

5. **Design doc drift** (LOW) — `07-deployment.md` still claims "Not provided in v1." This is misleading for new contributors.

### Risks

| Risk | Severity | Mitigation |
|------|----------|------------|
| Dockerfile breaks silently (no CI check) | MEDIUM | Add a `docker build` step to CI |
| Large image / slow builds (no `.dockerignore`) | LOW | Add `.dockerignore` |
| No health detection in production | MEDIUM | Add `HEALTHCHECK` instruction |
| Design docs mislead contributors | LOW | Update §7.5 to reflect Docker support |

## Verdict

### Overall: **PASS** — Docker image exists and is functional

The checklist item "No Docker image provided in v1" is **no longer accurate**. A complete Docker setup exists at the repo root:
- Multi-stage `Dockerfile` (builder + runner)
- `docker/nginx.conf` for static serving + API proxy
- `docker/start.sh` entrypoint that runs migrations and starts services

The Docker implementation actually exceeds the original "v1" scope by including nginx static serving (resolving D-03 as noted in report 0354_10.2.3). The remaining gaps (`.dockerignore`, `HEALTHCHECK`, CI validation, `docker-compose.yml`) are polish items, not core capability blockers.

### Recommended Actions

1. **Update `07-deployment.md` §7.5** — Change "Docker image: Not provided in v1" to reflect the current Docker + nginx setup
2. **Add `.dockerignore`** — Exclude `node_modules`, `.git`, `coverage/`, `dist/`, `*.log`
3. **Add `HEALTHCHECK`** — `HEALTHCHECK --interval=30s --timeout=3s CMD curl -f http://localhost:80/ || exit 1`
4. **Add Docker build step to CI** — At minimum, `docker build -t docuvia:ci .` to validate the Dockerfile doesn't break
5. **Consider `docker-compose.yml`** — For v1.1, include Postgres service for one-click deployment

### Status for Tracking Table

**PASS** — The Docker image is provided and functional. The design doc claim is stale but the implementation is real.
