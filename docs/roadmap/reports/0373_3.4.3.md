## Round 1 — Architecture & Design Review

### Design ↔ Implementation Alignment

**✅ Correctly implemented:**

1. `POST /sync/push` endpoint in `sync.ts` — full CQRS outbox handler with advisory locks and transactions (matches design spec for server-side processing).
2. Git hook template (`githook-template.sh`) — correctly captures branch name and commit hashes from post-push environment.

### Gaps / Deviations

1. **❌ CLI calls wrong server endpoint** — `cli.ts` calls `POST /api/projects/:id/sync` (a stub that only logs activity), instead of `POST /sync/push` (the actual CQRS outbox handler). The sync flow is non-functional.
2. **❌ `POST /projects/:id/sync` is a stub** — Only inserts an activity log row; does not process commits, update validity status, trigger generation, or write to orphan branch.
3. **❌ `CentralServerClient.sync()` calls `POST /sync`** — This route does not exist on the server. Server only has `POST /sync/push`. The client-to-server push path is disconnected.
4. **❌ CLI does not accept `--branch`/`--commits` flags** — The githook template passes these flags but the CLI only takes `<project_id>` positional argument.
5. **❌ CLI does not read `.docuvia/config.yaml` or `.docuvia/.snapshot-ref`** as specified in design docs.
6. **❌ CLI does not run `git fetch origin docuvia-knowledge`** after sync — breaking the local snapshot update.
7. **❌ No `POST /sync` route** — `CentralServerClient.sync()` calls this endpoint but it doesn't exist.
8. **❌ No `docuvia.sync` VS Code command** — Not registered in `extension.ts` or declared in `package.json` contributions.
9. **❌ `scripts/package.json` has no `bin` entry** — CLI is not installable as a `docuvia` command.

## Round 2 — Code Quality & Security Review

### Strengths

1. `POST /sync/push` correctly uses advisory locks and transactions for concurrent safety.
2. CLI uses `Bearer` token auth header correctly.
3. Git hook template correctly quotes variables.

### Issues Found

1. **⚠️ Medium — CLI uses `MCP_PAT` env var for auth:** Git hooks run in a limited environment and may not inherit `.env` files. Token provisioning for hook context is undocumented.
2. **⚠️ Medium — No input validation on project ID:** `cli.ts` passes `process.argv[3]` directly to URL template without validating it's a numeric ID.
3. **⚠️ Medium — No `bin` entry in `scripts/package.json`:** CLI cannot be installed as a command.
4. **⚠️ Medium — `scripts/package.json` has no build script:** No compiled output, CLI only runnable via `tsx`.
5. **🟢 Low — `cli.ts` uses `process.exit()` directly:** Makes code untestable without mocking.
6. **🟢 Low — No tests for CLI:** Zero unit or integration test coverage.

## Overall Verdict

**⚠️ WARN**

The `docuvia sync` CLI remains scaffolded but not functional. Since the last verification (2026-06-26), **no code changes** have been made to any of the relevant source files. All 10 findings are carried forward. The CLI calls the wrong endpoint, the server stub does not process sync, the githook is incompatible with the CLI interface, and the end-to-end sync flow (git hook → CLI → server → orphan branch → fetch) is not operational. The correctly-designed `POST /sync/push` CQRS endpoint exists but is never called by anything.
