## Round 1 — Architecture & Design Review

### Design ↔ Implementation Alignment

**✅ Correctly implemented:**

1. **Build artifact type detection** (`build-artifact-parser.ts`): `detectSubtype()` correctly identifies map/fv/fd/compile-log by extension and content heuristics. Well-structured with separate parsers per type.
2. **Parser implementations**: `parseMapFile`, `parseFvFile`, `parseFdFile`, `parseCompileLog` each handle GCC and MSVC patterns comprehensively. Top-N limiting (20 modules, 50 diagnostics) prevents unbounded output.
3. **Document type detection** (`document-parser.ts`): `detectDocType()` correctly maps extensions to `SupportedDocType` union type, including build artifact extensions (map, fv, fd, log).
4. **Worker isolation** (`document-parser.ts`): PDF/DOCX/PPTX parsing delegated to `child_process.fork` with 60-second timeout, 512 MB heap limit, and proper cleanup (SIGKILL on timeout, temp file removal). This satisfies ADR-012 and §8.7 security boundaries.
5. **Build artifact text extraction** (`document-parser.ts` L97-98): `extractText()` correctly calls `extractBuildArtifactText()` with `buffer.toString("utf-8")` for the build_artifact case. This path is **functional** when invoked from the `/document/upload` endpoint.
6. **MIME/extension whitelist** (`upload.ts`): `ALLOWED_MIMETYPES` and `ALLOWED_EXTENSIONS` sets correctly restrict uploads to known safe types.
7. **Upload middleware** (`upload.ts`): `documentUpload` correctly configured with 10 MB `fileSize` limit and `fileFilter` callback.

### Gaps / Deviations

1. **❌ CRITICAL: `memoryStorage()` — `req.file.path` undefined in build-artifact endpoint** (`ingest.ts` L421): The `/projects/:id/ingest/build-artifact` route uses `documentUpload.single("file")` which configures `multer.memoryStorage()`. With `memoryStorage()`, multer stores the file in **memory** as `req.file.buffer` and does **NOT** write to disk. Therefore `req.file.path` is `undefined`. Line 421 (`const filePath = req.file.path`) assigns `undefined`, then line 422 (`computeHashFromStream(filePath)`) and line 423 (`fs.promises.readFile(filePath, "utf-8")`) both fail with `ENOENT` or `TypeError`. **This endpoint is completely non-functional at runtime.**

2. **❌ CRITICAL: Same bug propagated to `documents.ts` L106**: The `/documents` POST route also accesses `req.file.path` after `documentUpload.single("file")`. Same root cause — `memoryStorage()` provides `buffer`, not `path`.

3. **⚠️ The `/document/upload` endpoint works but only by luck** (`ingest.ts` L237): This endpoint accesses `req.file.buffer` (correct for `memoryStorage()`). However, it bypasses `computeHashFromStream()` entirely — the `contentHash` for ADR-012's dedup-by-hash requirement is never computed on this path. Documents uploaded via `/document/upload` cannot be deduplicated by `contentHash`.

4. **⚠️ Missing magic byte validation** (`upload.ts`): Per §8.4, the design requires magic byte validation. The `fileFilter` only checks MIME type and extension — it does not validate the file signature bytes (e.g., `%PDF-` for PDFs, PK ZIP header for DOCX/PPTX). A malicious file with a `.pdf` extension but non-PDF content would pass the filter.

## Round 2 — Code Quality & Security Review

### Strengths

1. **Defensive temp file handling** in `document-parser.ts`: random filename via `crypto.randomBytes(8)`, cleanup in timeout/error/exit handlers, and `detached: false` to prevent zombie workers.
2. **Output limiting**: `build-artifact-parser.ts` caps sections to top 20, modules to 20, diagnostics to 50. This prevents unbounded memory growth on pathological inputs.
3. **ANSI escape stripping** (`ingest.ts` L424): Build logs commonly contain ANSI color codes; the regex `\x1b\[[0-9;]*[mG]` correctly strips them.
4. **Explicit TODO marker** in source (`upload.ts` L15): The code self-documents the known bug, which aids discoverability.

### Issues Found

1. **❌ Runtime crash — `req.file.path` is `undefined`** with `memoryStorage()`. Both `ingest.ts` L421-423 and `documents.ts` L106 will throw on every request. This is a **broken endpoint**, not just a quality issue.

2. **⚠️ No test coverage**: Zero test files found for upload, build-artifact parsing, or ingest artifact flow. A unit test exercising the `memoryStorage()` → `req.file.path` path would have caught this immediately.

3. **⚠️ `contentHash` not computed on `/document/upload` path**: ADR-012 requires `contentHash` (SHA-256) at ingestion time for deduplication. The working upload endpoint skips this entirely. Only the broken `/build-artifact` endpoint attempts it (and crashes).

4. **⚠️ Project name hardcoded as `Project ${projectId}`** (`ingest.ts` L429): The comment even says "We should fetch this". The hardcoded name is stored in the database, corrupting downstream queries.

5. **⚠️ No magic byte / file signature validation**: MIME type can be spoofed by the client. The `fileFilter` accepts `application/octet-stream` for any extension match, bypassing even the MIME check.

## Round 3 — Integration & Completeness Review

### Integration Correctness

1. **The `/document/upload` → `extractText()` → `extractBuildArtifactText()` path is functional** for build artifact files uploaded via the general document endpoint. The `detectDocType()` call correctly identifies `.map`, `.fv`, `.fd`, `.log` as `build_artifact`, and the parsing chain works correctly in memory.

2. **The dedicated `/build-artifact` endpoint is dead** — it will crash on every invocation due to `req.file.path` being undefined. No amount of correct downstream parsing can compensate for a middleware incompatibility.

3. **The `/documents` POST endpoint is also dead** for the same reason.

### Missing Coverage

1. **❌ No integration test** for the build-artifact upload flow. If one existed, it would fail immediately, revealing the bug.

2. **❌ `contentHash` deduplication** (ADR-012) is non-functional. On the working endpoint, it's not computed. On the broken endpoint, it crashes before reaching the DB.

3. **⚠️ No file type validation beyond MIME/extension** — spoofed uploads pass through unchanged.

4. **⚠️ The build-artifact endpoint does extra work** (ANSI stripping, hash computation) that the document-upload endpoint doesn't. Even if fixed, the two paths would produce different content for the same file (one strips ANSI, one doesn't), leading to inconsistent indexing.

## Overall Verdict

**❌ FAIL**

Two upload endpoints are completely non-functional at runtime due to the `memoryStorage()` / `req.file.path` incompatibility. The core parsing logic (`build-artifact-parser.ts`) is well-implemented and functionally correct — the failure is purely a middleware wiring issue. The `// TODO: [CRITICAL BUG FIX]` marker in `upload.ts` acknowledges the bug but it remains unfixed. The working `/document/upload` endpoint can process build artifacts via `extractText()`, but it skips `contentHash` computation (breaking ADR-012 dedup), doesn't strip ANSI codes, and provides no dedicated error handling for artifact-specific failures.
