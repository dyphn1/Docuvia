## Round 1 — Architecture & Design Review

### Design ↔ Implementation Alignment

**✅ Correctly implemented:**

1. **Ownership check middleware exists** — `checkProjectOwnership` function queries the project by ID and compares `project.ownerId !== userId` (line 31), returning 403 on mismatch.
2. **Both export routes gated** — Both `/projects/:id/export` (JSON) and `/projects/:id/export/md` (Markdown) pass through `checkProjectOwnership` middleware (lines 39, 128).
3. **Markdown export uses streaming** — `res.write()` with batched DB queries (100 per page) prevents OOM on large projects (lines 147–179). Good architectural decision.

### Gaps / Deviations

1. **❌ CRITICAL: Hardcoded auth bypass** — Line 23: `const userId = (req as any).user?.id || 1;`
   - The `(req as any).user?.id` is never populated (no auth middleware in the pipeline).
   - The `|| 1` fallback means `userId` is always `1` (the default owner).
   - **Impact:** Any authenticated-or-not user can export any project's data by simply specifying any `projectId`. The ownership check compares `project.ownerId !== 1` — and since `ownerId` defaults to `1` on all projects, **every user can export every project**.

2. **❌ No auth middleware in route pipeline** — `index.ts` applies rate limiting but no authentication/authorization middleware. The `req.user` object is never set. The export router has no `passport`, `jwt`, or session middleware applied.

3. **❌ Type-unsafe access** — `(req as any).user?.id` uses `as any` type assertion, indicating this is placeholder code that slipped into production.

4. **⚠️ Consistent pattern across the codebase** — Review tasks (`review_tasks.ts`) also implement their own ownership checks. However, that route at least requires a valid session (used in a connected context). The export endpoint has no such guard.

## Round 2 — Code Quality & Security Review

### Strengths

1. **Defense-in-depth structure** — The ownership check is isolated in its own middleware function, making it easy to verify and test independently.
2. **Streaming response for Markdown** — Uses `res.write()` in batches rather than buffering the entire project in memory. Demonstrates awareness of resource limits.
3. **Explicit error responses** — Returns 404 for missing projects, 403 for ownership mismatch. Clean error handling.
4. **`[CRITICAL BUG FIX]` TODO marker** — The developer who wrote the placeholder clearly knew this needed to be addressed. This is good hygiene.

### Issues Found

1. **🔴 CRITICAL: IDOR / Broken Access Control (CWE-639)**
   - The `userId = 1` fallback means the ownership check is effectively `project.ownerId !== 1`. Since `ownerId` defaults to `1` on every project (see `projects.ts` line 24: `.default(1)`), the check `project.ownerId !== userId` is always `1 !== 1` = `false` → **access is always granted**.
   - Any user (even unauthenticated) can export all knowledge graph data for any project.

2. **🔴 CRITICAL: Missing Authentication**
   - No JWT, session, or API key middleware is applied to the export routes in `index.ts`. The `req.user` object is never populated by any upstream middleware.

3. **🟡 MEDIUM: N+1 query in JSON export** — Lines 66–83: For each L2 node, a separate query fetches `l2NodeL1TagsTable` and `l3NodesTable`. Should use JOINs or batch queries.

4. **🟡 MEDIUM: N+1 query in Markdown export** — Line 167: Inside the streaming loop, each L2 node triggers a separate `l3Nodes` query. Could be pre-fetched or JOINed.

5. **🟢 LOW: Missing `return` on early `res.end()`** — The markdown endpoint calls `res.end(); return;` which is correct, but in the JSON endpoint, successful responses use `return res.json(...)` which is fine. No bug here, just noting the pattern.

## Round 3 — Integration & Completeness Review

### Integration Correctness

1. **Route registration works** — `exportRouter` is correctly mounted in `index.ts` (line 47). Endpoints are reachable.
2. **Middleware order is correct** — `checkProjectOwnership` runs before the handler logic (standard Express middleware chaining).
3. **Database queries are correct** — The Drizzle ORM queries for projects, L2 nodes, L3 nodes, L1 tags, and commits all use proper `eq()` conditions and `projectId` scoping.

### Missing Coverage

1. **No auth middleware integration** — The route assumes an upstream auth layer will populate `req.user.id`. No such layer exists in the current codebase. The export endpoints are effectively unauthenticated.
2. **No rate limiting on export** — Export operations are data-intensive (dump entire projects). No specific rate limiter is applied (only `standardLimiter` globally).
3. **No audit logging** — Exporting sensitive knowledge graph data should be logged for compliance. No `activity_log` entries are created.
4. **No tests for ownership check** — No unit or integration tests verify the IDOR fix. Without tests, this regression can reoccur silently.
5. **No CORS consideration** — If the export endpoint is meant for external consumers (e.g., CI pipelines), CORS headers or API token auth should be considered.

## Overall Verdict

**❌ FAIL**

The export endpoint contains a **critical IDOR vulnerability** (CWE-639: Authorization Bypass Through User-Controlled Key). The `checkProjectOwnership` middleware is rendered non-functional by the `userId = 1` fallback combined with the absence of any authentication middleware. Since all projects default to `ownerId = 1`, the ownership check `project.ownerId !== userId` always evaluates to `false` — granting unrestricted access to every project's knowledge graph data (L1 tags, L2 nodes, L3 nodes with implementation rules, commits) to any requester.

This directly violates the Phase 6 master roadmap requirement: *"Export endpoints must rigidly verify `userId` against `projectId` ownership to prevent unauthorized data dumps."*

**Fix required:**
1. Implement authentication middleware (JWT, session, or API key) that populates `req.user.id` from a verified token.
2. Remove the `|| 1` fallback — unauthenticated requests should return 401.
3. Once auth is in place, write integration tests that verify:
   - Owner can export their own project (200)
   - Non-owner cannot export another's project (403)
   - Unauthenticated requests get 401
