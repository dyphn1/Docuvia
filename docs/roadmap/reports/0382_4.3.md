## Round 1 — Architecture & Design Review

### Design ↔ Implementation Alignment

**✅ Correctly implemented:**

1. **Business logic in `/mcp/impact_analysis` (lines 182-227)** — The core impact analysis algorithm is structurally sound: queries `node_links` for incoming links to a target L2 node, resolves source node names, counts L3 decisions. This matches ADR-007's "Graph RAG: Traverses `node_linksTable` to find structural dependencies."
2. **Business logic in `/mcp/get_dependencies` (lines 130-180)** — Symmetrically correct: outgoing links for dependencies, incoming for dependents.
3. **Auth middleware (lines 20-48)** — PAT-based Bearer token authentication on all `/mcp/*` routes is correctly implemented with `crypto.timingSafeEqual`.
4. **Search knowledge endpoint (lines 110-128)** — Delegates to `routeQuery()` from intent-router, which is the correct integration point per ADR-007.

### Gaps / Deviations

1. **❌ CRITICAL: 4 undefined Zod query schemas render 5 GET endpoints non-functional:**
   - `ModuleQuery` — used at lines 131 and 183 for `/mcp/get_dependencies` and `/mcp/impact_analysis`
   - `SearchKnowledgeQuery` — used at line 111 for `/mcp/search_knowledge`
   - `RetrieveOriginalQuery` — used at line 90 for `/mcp/retrieve_original`
   - `DecisionRecordQuery` — used at line 230 for `/mcp/get_decision_record`
   - None of these schemas are defined or imported anywhere in the codebase. Every request to these endpoints crashes at the `.safeParse()` call before any business logic executes.

2. **⚠️ TimingSafeEqual vulnerability (known, TODO marker present):**
   - Line 38-40: `providedToken.length !== expectedToken.length` uses character count, not byte length. Multibyte characters cause `Buffer.from()` to yield different sizes, crashing with `RangeError`. The TODO marker at line 36 acknowledges this but the fix has not been applied.

## Round 2 — Code Quality & Security Review

### Strengths

1. **Auth middleware is properly scoped** — Applied via `router.use("/mcp", ...)` so all MCP routes are protected. No fallback values or bypass paths.
2. **Input sanitization** — `sanitizeLikeInput()` is used before LIKE queries, preventing SQL injection via `%` and `_` wildcards.
3. **Error handling** — All async route handlers wrap logic in try/catch with structured logging.
4. **No hardcoded secrets** — PAT loaded from `process.env.MCP_PAT`.

### Issues Found

1. **❌ CRITICAL: Undefined schemas = 0% endpoint coverage for 5 routes:**
   - TypeScript compilation fails with 5× TS2304 errors:
     - `mcp.ts(90,18): Cannot find name 'RetrieveOriginalQuery'`
     - `mcp.ts(111,18): Cannot find name 'SearchKnowledgeQuery'`
     - `mcp.ts(131,18): Cannot find name 'ModuleQuery'`
     - `mcp.ts(183,18): Cannot find name 'ModuleQuery'`
     - `mcp.ts(230,18): Cannot find name 'DecisionRecordQuery'`
   - esbuild passes (no typecheck at bundle time) so the server starts, but every request to these GET endpoints throws `ReferenceError: ModuleQuery is not defined` at runtime.
   - The business logic below the schema check is correct — this is dead code that can never execute.

2. **⚠️ Medium: `list_projects` N+1 query pattern (lines 50-77):**
   - For each project, 2 separate DB queries (L2 count + L2 IDs loop with L3 count per L2). With 100 projects, this produces 1 + 100 + 100 = 201 queries per request. Should be a single aggregated query.

3. **⚠️ Low: Auth timingSafeEqual crash (line 38-40):**
   - Known TODO. Not exploitable for auth bypass (the comparison still happens), but causes denial-of-service.

## Round 3 — Integration & Completeness Review

### Integration Correctness

1. **MCP route architecture** — The Express router is correctly structured with auth middleware applied globally and business logic in individual handlers.
2. **Graph traversal integration** — `/mcp/impact_analysis` correctly implements the "Neighbor Infection" pattern from ADR-007 by querying `node_links` for incoming edges to the target node.
3. **Intent router delegation** — `/mcp/search_knowledge` and `POST /mcp/query` correctly delegate to `routeQuery()`.

### Missing Coverage

1. **❌ 5 of 7 GET endpoints are completely non-functional** due to undefined schemas. Only `/mcp/list_projects` and `POST /mcp/query` (which uses inline `z.object()`) work.
2. **⚠️ No integration tests** for MCP routes — the undefined schemas would be caught by any test that actually invokes these endpoints.
3. **⚠️ Impact analysis does not traverse transitively** — Returns only direct dependents (1-hop). For true impact analysis, multi-hop traversal (2nd, 3rd degree) would be expected, but this is a scope decision, not a bug.

## Overall Verdict

**❌ FAIL**

The core business logic for impact analysis and dependency retrieval is correctly implemented and aligns with ADR-007's Graph RAG strategy. However, 4 undefined Zod query schemas (`ModuleQuery`, `SearchKnowledgeQuery`, `RetrieveOriginalQuery`, `DecisionRecordQuery`) cause 5 of 7 MCP GET endpoints to throw `ReferenceError` at runtime. TypeScript compilation fails (5× TS2304). These endpoints have 0% functional coverage — they appear correct on casual reading but can never execute. This is a complete failure of the MCP GET API surface.

**Fix required:** Define and export the 4 missing Zod schemas (or replace with inline `z.object()` declarations) to restore basic functionality.
