readDynamicDependencyEvidenceState() never reads corrupt, wrong-shaped or missing #393 evidence as 'no runtime imports'. It returns unavailable with reason corrupt-json | not-array | invalid-record | missing; one invalid record makes the whole set untrusted (never partially used). A missing row is only benign when no JS/TS source is tracked. ImpactService.getDynamicEvidenceAvailability() surfaces it and ImpactResult.dynamicEvidenceUnavailable + a lower-bound note report it. An ingestion batch that meets an unavailable set rescans every tracked JS/TS source instead of writing an 'available' partial set.
